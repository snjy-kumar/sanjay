What it is
</h2>
<p>I “controlled” inputs by setting <code>value</code> and forgetting <code>onChange</code>. React warned. The caret jumped. Typing felt broken, and I blamed the browser. The browser was doing what a controlled input asks: on every render, the DOM value is forced back to the React state.</p>
<p>Controlled means React owns the value. Each keystroke has to call a setter, and the next render passes the new <code>value</code>. Uncontrolled means the DOM owns the value: <code>defaultValue</code> on mount, and a ref when I need a snapshot at submit time. Mixing them, or flipping from <code>undefined</code> to a string later, is the half-controlled trap.</p>
<p><code>value={title}</code> with <code>onChange={() =&gt; {}}</code> is still controlled. The handler runs and then writes nothing, so the input snaps back. An empty <code>onChange</code> is not a listener.</p>
<p>I pick one mode per field and stay there. Controlled when I need to validate, disable a button, or derive something on each change. Uncontrolled when I only need the value at submit and the field is otherwise simple.</p>
</section>

New
</h2>
<p><strong>Right approach: pair value with a setter, or use defaultValue and read later</strong></p>
<p><strong>Best case.</strong> Controlled: every keystroke is in state and available for a character count or a disabled button. Uncontrolled: the form owns the DOM and submit reads it once.</p>
<p><strong>Worst case.</strong> Switching a field from uncontrolled to controlled by going from <code>value={undefined}</code> to <code>value={title}</code> after the first change. Pick a mode on the first render and keep it.</p>
<p>After: the input is controlled for the whole lifetime of the component.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use a controlled input when render needs the current text. Use <code>defaultValue</code> when the DOM can own it until submit. Add <code>readOnly</code> when the value is shown and must not change. Do not pass <code>value</code> without updating it, and do not pass both <code>value</code> and <code>defaultValue</code>.</p>
<div class="when">
<div class="when-row"><span>Render depends on the text</span><span class="when-choice">value and onChange</span></div>
<div class="when-row"><span>Read the text at submit only</span><span class="when-choice">defaultValue</span></div>
<div class="when-row"><span>Show a value nobody should edit</span><span class="when-choice">value and readOnly</span></div>
<div class="when-row"><span>Both value and defaultValue</span><span class="when-choice">pick one</span></div>
</div>
</section>
