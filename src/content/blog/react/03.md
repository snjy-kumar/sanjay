What it is
</h2>
<p>I used the array index as a key for years because the warning disappeared. Then I reordered a list in a personal project and watched inputs keep the wrong values. The row components were reused by position. The data moved. The local state did not.</p>
<p>A key is an identity across renders, not a label for humans. React matches the previous tree to the next tree by key. An index says “I am whatever currently sits in slot 2.” That is true only when the list never inserts, deletes, filters, or reorders.</p>
<p><code>key={Math.random()}</code> is worse. It changes every render, so React throws the row away and mounts a new one. Focus, typed text, and any internal state die on each keystroke.</p>
<p>I take a stable id from the data: <code>id</code>, a slug, or an id I created when the item was added and then stored on the item. I do not generate that id during render. The key belongs on the element inside the <code>map</code>, not on a child inside that element.</p>

New
</h2>
<p><strong>Right approach: key each row with a stable id that was stored when the item was created</strong></p>
<p><strong>Best case.</strong> Sorting and deleting preserve the right input state, and React updates the row in place instead of remounting it.</p>
<p><strong>Worst case.</strong> Reusing an id after deleting an item, or keying by a label the user can edit. Two rows share an identity and React merges them.</p>
<p>After: the key is the item’s id, on the element the array returns.</p>

When to use which
</h2>
<p>Use an index only for a list you truly never reorder, filter, or insert into, and that holds no state. Prefer an id from the data in every other case. Never call <code>Math.random</code> or <code>crypto.randomUUID</code> inside the key expression during render. If the server has no id, create one when you append the item and keep it on the object.</p>
<div class="when">
<div class="when-row"><span>List can move, filter, or insert</span><span class="when-choice">stable id</span></div>
<div class="when-row"><span>Truly static, stateless list</span><span class="when-choice">index is tolerable</span></div>
<div class="when-row"><span>A brand new row the user just added</span><span class="when-choice">id created at insert time</span></div>
<div class="when-row"><span>Key generated in render</span><span class="when-choice">do not</span></div>
</div>
</section>
