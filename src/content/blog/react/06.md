What it is
</h2>
<p>A search box in a personal project kept querying the first thing I typed. The handler had closed over <code>query</code> from the render that created it. React had not forgotten the new state. The callback had never seen it.</p>
<p>Every function created during render sees the props and state from that render. That is ordinary JavaScript. It surprises me when the function lives longer than the render: a <code>setInterval</code> started in an effect with <code>[]</code>, a listener I added once, an async request that finishes after the user has typed something else.</p>
<p>If the update does not need the old value’s identity, I use the functional form: <code>setItems((prev) =&gt; [...prev, next])</code>. The queue hands me the latest state, so the closure does not matter. If an effect reads a value, that value belongs in the dependency array, and the effect should re-subscribe.</p>
<p>A long-lived callback that must see the latest value without re-subscribing can read a ref I update every render. I use that sparingly. The first question is still: does this callback outlive the render that made it?</p>
</section>

New
</h2>
<p><strong>Right approach: update from the previous state, or list the values you read, or keep a ref on purpose</strong></p>
<p><strong>Best case.</strong> The interval increments forever without restarting. A listener that must see <code>query</code> reads <code>queryRef.current</code>, which was assigned on the latest render.</p>
<p><strong>Worst case.</strong> A ref used as secret state for something the screen should show. Mutating the ref will not re-render. If the UI depends on it, I wanted state.</p>
<p>After: appending an item uses the previous array React passes in, not an array captured earlier.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use a functional update when the next state depends on the previous state. Put a value in the dependency array when an effect or memo reads it and should restart. Use a ref when a long-lived subscription must read the latest value and re-subscribing is wrong. If I cannot explain which of the three I am in, I print the value inside the callback once. The past is usually sitting right there.</p>
<div class="when">
<div class="when-row"><span>Next state depends on previous state</span><span class="when-choice">functional update</span></div>
<div class="when-row"><span>Effect should rerun when a value changes</span><span class="when-choice">list it as a dependency</span></div>
<div class="when-row"><span>A stable listener needs the latest value</span><span class="when-choice">ref updated each render</span></div>
<div class="when-row"><span>The screen should show the change</span><span class="when-choice">state, not a ref</span></div>
</div>
