What it is
</h2>
<p>The boundary between <code>useState</code> and <code>useRef</code> is often misunderstood. I have seen developers store a timer ID in <code>useState</code>, which unnecessarily re-renders the component just to remember a number. And I have seen developers mutate <code>countRef.current++</code> and wonder why the number on the screen refuses to update.</p>
<p>Both hooks persist values across renders. But <code>useState</code> tells React: “this value is used to calculate the UI; when it changes, re-render the component so the user sees the update.” Mutating state schedules a render pass.</p>
<p><code>useRef</code> is an escape hatch. It holds a plain JavaScript object <code>&#123; current: initialValue &#125;</code> that survives re-renders, but mutating <code>.current</code> is completely invisible to React’s render engine. No render is scheduled, and no DOM updates occur.</p>
<p>The rule is simple: if changing the value should immediately change what appears on the screen in JSX, it must be state. If the value is needed only by event handlers or effects behind the scenes—a timer ID, a DOM element reference, a previous value tracker—it belongs in a ref.</p>
</section>

New
</h2>
<p><strong>Right approach: state for UI feedback, refs for internal handles</strong></p>
<p><strong>Best case.</strong> The UI reacts instantaneously to user actions, and internal timers or DOM focus nodes operate without triggering redundant renders.</p>
<p><strong>Worst case.</strong> Over-using state when a variable is only read inside an async callback. Always ask: does JSX render this value directly?</p>
<p>After: state drives the visible text; refs hold DOM nodes or timers.</p>

<h2>

When to use which
</h2>
<p>Keep a clear boundary: if a value influences what JSX renders, choose state. If a value is needed only for imperative API calls or timer IDs, choose a ref.</p>
<div class="when">
<div class="when-row"><span>DOM focus or measure</span><span class="when-choice">useRef</span></div>
<div class="when-row"><span>Timer / request ID</span><span class="when-choice">useRef</span></div>
<div class="when-row"><span>Previous value comparison</span><span class="when-choice">useRef</span></div>
<div class="when-row"><span>Visible count / input text</span><span class="when-choice">useState</span></div>
</div>
</section>
