What it is
</h2>
<p>I put values in <code>useState</code> that never changed the screen, and I put values in <code>useRef</code> that the screen was supposed to show. The first caused extra renders. The second caused a counter that incremented in the console and stayed frozen in the UI.</p>
<p>State is a value that, when replaced, should render again. A ref is a box that survives renders. Writing <code>ref.current</code> does not notify React. That is what I want for a DOM node, a timer id, or the latest copy of a value for a long-lived listener.</p>
<p>Reading <code>ref.current</code> during render to decide what to display is the trap. Render should be a function of props and state. The ref can be read in an effect or a handler, after the commit, which is also when DOM nodes exist. <code>inputRef.current?.focus()</code> belongs in a handler or an effect, not in the render body.</p>
<p>If I mutate a ref and then look for a way to force a render, I wanted state. Refs are not a private second store for UI.</p>
</section>

New
</h2>
<p><strong>Right approach: state for what render prints, refs for nodes and ids</strong></p>
<p><strong>Best case.</strong> The count updates the paragraph. The ref holds the input. Focus runs after the click, when the node exists.</p>
<p><strong>Worst case.</strong> A ref copied into state on every render “so the UI updates.” That is state with extra steps. I store the value in state directly.</p>
<p>After: <code>setCount</code> is the only way the number changes, and the ref is only the element.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Choose state when a change should be visible. Choose a ref for a DOM node, a timer id, a previous value, or the latest copy of state for a callback that must not re-subscribe. Do not read a ref to compute JSX. Do not put a DOM node in state.</p>
<div class="when">
<div class="when-row"><span>The screen prints the value</span><span class="when-choice">state</span></div>
<div class="when-row"><span>A DOM node or timer id</span><span class="when-choice">ref</span></div>
<div class="when-row"><span>Latest value inside a stable listener</span><span class="when-choice">ref</span></div>
<div class="when-row"><span>You need a re-render after a write</span><span class="when-choice">state</span></div>
</div>
</section>
