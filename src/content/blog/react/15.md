What it is
</h2>
<p>When I open my own components now, I do not ask whether they import React. I ask whether they behave honestly when the data is late, empty, wrong, or moving.</p>
<p>The habits in this series are the checklist. Source state stays, derived labels are computed. Clicks live in handlers. Lists have stable keys. Effects subscribe and clean up, including aborting a fetch. Hooks run in a fixed order. Context is rare. A form field is either controlled on purpose or left to the DOM. Loading, error, and empty each have a node.</p>
<p>A person skimming a screenshot can miss all of that. Clicking through the empty state and the failed request does not. I am still cleaning older projects. The point of keeping them public is the standard, not a single happy path.</p>
<p>I would rather fix one component’s error branch this week than rewrite the tree. A small diff that adds a retry, a real key, or a cleanup is the signal I want the next reader to see.</p>
</section>

<h2>

When to use which
</h2>
<p>When I review a component I look for duplicated state, an effect that should have been a handler, an index key, a fetch without cleanup, and a missing empty state. I fix the one that will confuse the next click. I do not add memoization unless I can name the cost.</p>
<div class="when">
<div class="when-row"><span>A label repeated in state</span><span class="when-choice">derive it</span></div>
<div class="when-row"><span>A click stored as a flag</span><span class="when-choice">handle the event</span></div>
<div class="when-row"><span>A moving list</span><span class="when-choice">stable keys</span></div>
<div class="when-row"><span>A request tied to the screen</span><span class="when-choice">status plus abort</span></div>
</div>
