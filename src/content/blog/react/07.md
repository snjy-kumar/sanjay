What it is
</h2>
<p>I once wrote <code>if (user) { useEffect(...) }</code>. It worked until logout. Then the component rendered with fewer hooks than the render before, and React lost track of which state belonged to which call. The warning was correct.</p>
<p>Hooks are matched by call order, not by name. React keeps a list. If the first render calls <code>useState</code>, then <code>useEffect</code>, every later render must do the same, the same number of times. A hook inside <code>if</code>, inside a loop, or after a conditional <code>return</code> changes that list.</p>
<p>The condition belongs inside the hook or after the hooks. I always call <code>useEffect</code>, and the effect returns immediately when <code>user</code> is null. The early return of the UI comes after those calls, so logout still runs the same hooks and then renders nothing.</p>
<p>Custom hooks are hooks too. Calling <code>useProfile(user)</code> only sometimes is the same bug. The linter rule <code>react-hooks/rules-of-hooks</code> is the check I treat like a type error.</p>
</section>

<p><strong>Worst case.</strong> Logout, a feature flag, or a loading branch changes how many hooks run. State from hook 2 is read as hook 1, or React throws and the screen dies.</p>

New
</h2>
<p><strong>Right approach: call every hook unconditionally, then branch</strong></p>
<p><strong>Best case.</strong> Login and logout run the same hooks. The effect cleans up or no-ops when <code>user</code> is null, and the UI branches afterward.</p>
<p><strong>Worst case.</strong> An unconditional hook that still does illegal work, such as an effect with a missing dependency. Order is necessary, not sufficient.</p>
<p>After: both renders call <code>useEffect</code> once, in the same place.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Call hooks at the top level of the component or custom hook, in a fixed order. Put conditions inside the effect, the handler, or the returned UI. Do not put hooks in loops or nested functions. If the linter flags a conditional hook, I move the call up before I debate it.</p>
<div class="when">
<div class="when-row"><span>Work depends on a value</span><span class="when-choice">condition inside the hook</span></div>
<div class="when-row"><span>UI depends on a value</span><span class="when-choice">return after the hooks</span></div>
<div class="when-row"><span>Shared hook logic</span><span class="when-choice">custom hook called unconditionally</span></div>
<div class="when-row"><span>Hook inside if or a loop</span><span class="when-choice">move it out</span></div>
</div>
</section>
