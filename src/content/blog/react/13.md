What it is
</h2>
<p>Two bugs kept showing up in my data loading. The first was a waterfall: wait for A, then start B, even when B did not need A. The second was lifetime: I navigated away, the request finished, and <code>setState</code> applied a result the screen no longer wanted. The old “setState on an unmounted component” warning is gone, but the race is not. A late response can still replace newer data.</p>
<p>Independent requests belong in one <code>Promise.all</code>, or in sibling effects that start together. I only await in series when the second call needs the first call’s result, such as an id I do not have yet.</p>
<p>Each effect gets an <code>AbortController</code>. The cleanup calls <code>abort()</code>. <code>fetch</code> rejects with an <code>AbortError</code>, and I ignore that error. I also ignore a resolution if a newer effect has already started, in case a request cannot be aborted. The controller’s signal is passed into <code>fetch</code>.</p>
<p>Fast UI here is mostly “do not wait for something that is not a prerequisite,” plus “do not paint a result after its owner has left.”</p>
</section>

New
</h2>
<p><strong>Right approach: start independent work together and abort it when the effect cleans up</strong></p>
<p><strong>Best case.</strong> A and B overlap. Changing <code>id</code> aborts the previous fetch. An abort does not flip the error UI.</p>
<p><strong>Worst case.</strong> Aborting a request the server still finishes, and a non-fetch client that ignores the signal. Then I also ignore resolutions after cleanup with a cancelled flag.</p>
<p>After: the effect that starts the load is the effect that cancels it.</p>

<section class="section" id="when">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Sequence requests only when one result is an input to the next. Otherwise start them together. Always pass an abort signal from the effect that owns the screen, and ignore the abort error. Check <code>res.ok</code> before treating the body as success.</p>
<div class="when">
<div class="when-row"><span>B needs a value from A</span><span class="when-choice">await in series</span></div>
<div class="when-row"><span>A and B are independent</span><span class="when-choice">Promise.all</span></div>
<div class="when-row"><span>The component or id changes</span><span class="when-choice">abort on cleanup</span></div>
<div class="when-row"><span>The client cannot abort</span><span class="when-choice">ignore stale resolutions</span></div>
</div>
</section>
