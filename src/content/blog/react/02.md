What it is
</h2>
<p>I used to put button work in <code>useEffect</code>. Click, set a flag, let the effect see the flag, then fetch or navigate. It felt like the React way to “do something after a change.” It was an event handler with an extra render and extra bugs.</p>
<p>Effects run because something rendered differently, not because a person clicked. They also re-run when dependencies change. A save effect that lists <code>draft</code> will save again when the draft changes, even if nobody pressed the button. In development, Strict Mode runs setup twice, so an effect-shaped click can fire twice.</p>
<p>A click handler runs because of the click. <code>async function onSave()</code> can set <code>saving</code>, await <code>saveDraft(draft)</code>, and clear the flag in <code>finally</code>. The trigger is obvious. The draft it closes over is the draft from that event.</p>
<p>I still use effects to synchronize with something outside React: a subscription, a document title, a listener. If the only reason to run is a gesture, the gesture’s handler owns the work.</p>
</section>

Old

<p><strong>Wrong approach: set a flag in the handler and do the work in an effect</strong></p>
<p><strong>Best case.</strong> The flag is set once, the draft never changes afterward, and I remember to reset the flag. The effect happens to run a single time.</p>
<p><strong>Worst case.</strong> The effect re-runs on every draft change, or Strict Mode double-invokes it, and I persist two copies or navigate twice.</p>

New

<p><strong>Right approach: put gesture work in the event handler and keep effects for outside synchronization</strong></p>
<p><strong>Best case.</strong> One click, one save. <code>finally</code> clears <code>saving</code> on success and on failure. Editing the draft does not submit.</p>
<p><strong>Worst case.</strong> A handler that also subscribes to a window event and never unsubscribes. That subscription still belongs in an effect with a cleanup.</p>
<p>After: <code>onSave</code> is the only path that calls <code>saveDraft</code>.</p>

<section class="section" id="when">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>If a person started it, put it in the handler: save, navigate, open, submit. If it should stay in sync with props or with an external system for as long as the component is shown, put it in an effect and return a cleanup. Do not encode a click as state just to satisfy a dependency array.</p>
<div class="when">
<div class="when-row"><span>Click, submit, or key handler</span><span class="when-choice">event handler</span></div>
<div class="when-row"><span>Subscribe while mounted</span><span class="when-choice">effect with cleanup</span></div>
<div class="when-row"><span>Document title matching a prop</span><span class="when-choice">effect</span></div>
<div class="when-row"><span>A flag whose only job is to trigger work</span><span class="when-choice">delete the flag</span></div>
</div>
</section>
