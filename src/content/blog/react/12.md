What it is
</h2>
<p>The instinct to avoid duplication often leads to a single, monolithic UI component. I once built a <code>&lt;Card /&gt;</code> that accepted twenty props: <code>hasHeader</code>, <code>headerIcon</code>, <code>isElevated</code>, <code>size</code>, <code>actionButtonText</code>, <code>onActionClick</code>, <code>secondaryAction</code>, and a dozen booleans.</p>
<p>Every time a designer added a slightly different layout—a card with a badge in the top right, or a card where the title was below the image—I had to add another prop, another ternary operator, and another optional callback. The component became a fragile maze of conditionals that no one could safely edit without breaking three other screens.</p>
<p>Duplication is far cheaper than the wrong abstraction. When you find yourself passing five configuration props just to customize what a child node renders, the solution is not more props—it is composition. Using <code>children</code> allows callers to assemble layout pieces directly without teaching the container about every possible permutation.</p>
<p>A good component provides a solid container or layout primitive. It does not dictate every pixel of its children through props.</p>
</section>

New
</h2>
<p><strong>Right approach: assemble layout slots and children at the call site</strong></p>
<p><strong>Best case.</strong> The caller has full freedom to reorder elements, add custom icons, or style specific text without touching the card's implementation.</p>
<p><strong>Worst case.</strong> Slightly more lines of code at the call site, but zero complexity inside the component library.</p>
<p>After: natural composition using regular JSX elements inside children.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use simple props for primitive values like labels and variants. Reach for composition as soon as props dictate layout structure or conditional elements.</p>
<div class="when">
<div class="when-row"><span>Color variants (primary, danger)</span><span class="when-choice">variant prop</span></div>
<div class="when-row"><span>Custom buttons or badges</span><span class="when-choice">children slots</span></div>
<div class="when-row"><span>Component has &gt;6 styling props</span><span class="when-choice">split into compound parts</span></div>
<div class="when-row"><span>One-off unique page layout</span><span class="when-choice">write plain HTML/JSX</span></div>
</div>
</section>
