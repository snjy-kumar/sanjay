What it is
</h2>
<p>Annotating a variable is local. Annotating a function is a contract every call site inherits. The expensive early habit is <code>function save(data) { ... }</code> — under <code>noImplicitAny</code> that is an error; with the flag off, <code>data</code> is <code>any</code> — or writing an explicit return of <code>any</code> “just for now” and never coming back.</p>
<p>Type the parameters first. If the return expression is obvious, let TypeScript infer it: a function that returns <code>post.title</code> does not need you to write <code>: string</code> unless you want to lock it. For a public helper used in more than one place, write the return type anyway. The annotation is what you meant to return. Inference is what you happened to return. When they disagree, you want the error at the helper, not at a distant caller.</p>
<p>A return annotation is not a validator. <code>return res.json() as Promise&lt;Post&gt;</code> makes the checker treat the body as <code>Post</code> without looking at it. <code>fetch</code>’s <code>json()</code> is <code>Promise&lt;any&gt;</code>. The honest contract types the inputs, types the promised output, checks <code>res.ok</code>, and parses the JSON into that output. The assertion is a hole you can see; it is not the design.</p>
<p>Two personal-project helpers share a save path: a React form and a small Node script. The first version was <code>save(data)</code> returning whatever <code>fetch</code> produced. One caller passed <code>{ name }</code> and the other passed <code>{ title }</code>. Both compiled. The route wanted <code>title</code>. The script then read <code>saved.id</code> off a value that was still <code>any</code>, so a missing id was a runtime crash instead of a type error at the helper.</p>

Old
</h2>
<p><strong>Wrong approach: untyped parameters and <code>any</code> returns</strong></p>
<p><strong>Best case.</strong> A function used once, directly under the call, with data built in that same block, deleted when the experiment ends. You never cross a file boundary.</p>
<p><strong>Worst case.</strong> <code>save</code> is imported in several places. Each caller invents a shape. <code>res.json()</code> returns <code>any</code>, so <code>saved.id.toUpperCase</code> type-checks even when the server returned <code>{ error }</code>. The bug shows up as a thrown method call on undefined, far from the fetch.</p>

New
</h2>
<p><strong>Right approach: parameters typed, public returns annotated</strong></p>
<p><strong>Best case.</strong> <code>SaveInput</code> rejects a payload without <code>title</code> at every call site. <code>Promise&lt;Saved&gt;</code> means a refactor that returns the raw <code>Response</code> fails in <code>save</code>, not in the form. <code>titleOf</code> stays inferred because the expression is the type. Autocomplete on the result is the real <code>id</code>.</p>
<p><strong>Worst case.</strong> You annotate a lie. <code>Promise&lt;Post&gt;</code> plus <code>as Promise&lt;Post&gt;</code> looks like a contract and is only a cast. Callers trust it. The server changes the body and TypeScript stays green. An explicit return type helps only if the value you return was actually checked or built from checked pieces.</p>
<p>After: <code>id</code> is a string, the promise is <code>Post</code>, and <code>title</code> is only read after <code>parsePost</code> has checked it.</p>

<section class="section" id="when">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Enable <code>noImplicitAny</code> so an untyped parameter is a mistake you see immediately. Type every parameter on exported functions. Let local, obvious returns be inferred. Annotate return types on helpers you import from more than one module, and on anything <code>async</code> whose payload crosses I/O — then make the returned value satisfy that annotation by parsing, not by <code>as</code>. Check <code>res.ok</code> before reading the body. Keep <code>Response</code> inside the helper so callers receive the domain type, not the transport type.</p>
<div class="when">
<div class="when-row"><span>A helper used in more than one place</span><span class="when-choice">type the parameters</span></div>
<div class="when-row"><span>A local return that is obvious</span><span class="when-choice">infer it</span></div>
<div class="when-row"><span>An async payload that crosses I/O</span><span class="when-choice">annotate and parse</span></div>
<div class="when-row"><span>The caller should not see the transport</span><span class="when-choice">return the domain type</span></div>
</div>
</section>
