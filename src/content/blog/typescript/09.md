What it is
</h2>
<p>I ignored generics until a personal project made me copy the same helper three times, once for notes, once for tags, and once for numbers. The textbook pages full of conditional types were not what I needed. I needed one function that kept the type of the value it returned.</p>
<p>A generic is a type parameter. <code>function first&lt;T&gt;(items: T[]): T | undefined</code> says: whatever element type the caller passes, the result is that same type, or <code>undefined</code> when the array is empty. Call it with <code>number[]</code> and the result is <code>number | undefined</code>. Call it with <code>Post[]</code> and the result is <code>Post | undefined</code>. Nothing is erased.</p>
<p><code>any[]</code> looks shorter and then poisons the call site. <code>const n = first([1, 2])</code> becomes <code>any</code>, so <code>n.toFixed</code> is allowed even after a later refactor returns a string. A default type parameter can be useful (<code>ApiResponse&lt;T = unknown&gt;</code>), but I leave it off until a call site is actually annoying to write.</p>
<p>Most days I only need two shapes: a function generic for a helper, and a type generic for a wrapper such as <code>ApiResponse&lt;T&gt;</code>. If I am stacking three type parameters to avoid a one-line interface, I stop and write the interface.</p>

New
</h2>
<p><strong>Right approach: one type parameter that the argument fills in</strong></p>
<p><strong>Best case.</strong> Each call site keeps autocomplete. An empty array is <code>T | undefined</code>, so I have to handle “nothing there” before I read a field.</p>
<p><strong>Worst case.</strong> A generic so unconstrained that <code>T</code> can be anything, including a value I meant to validate. Generics do not check runtime shape. They only preserve a type I already have.</p>
<p>After: the element type is the return type, and the empty slot stays optional.</p>

When to use which
</h2>
<p>Reach for <code>&lt;T&gt;</code> when a helper would otherwise use <code>any</code>, or when two copies of a function differ only by the type they mention. Skip generics when the function has one concrete type. Do not use a generic to avoid parsing untrusted JSON: parse to a concrete type, then let <code>T</code> describe that result.</p>
<div class="when">
<div class="when-row"><span>One concrete input and output</span><span class="when-choice">name the types</span></div>
<div class="when-row"><span>Same helper, many element types</span><span class="when-choice">function generic</span></div>
<div class="when-row"><span>A wrapper around a payload</span><span class="when-choice">type generic</span></div>
<div class="when-row"><span>Untrusted JSON</span><span class="when-choice">parse, then type</span></div>
</div>
</section>
