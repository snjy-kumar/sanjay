What it is
</h2>
<p><code>unknown</code> is the type I use when a value has entered my app and I have not proved what it is. <code>fetch</code> JSON, a request body, and anything another process wrote are <code>unknown</code> until a parser says otherwise. <code>any</code> would let me skip that proof. <code>unknown</code> will not.</p>
<p>The rule I follow is short. Outside the boundary the type is <code>unknown</code>. A function such as <code>parsePost</code> either throws or returns <code>Post</code>. Inside the app I take <code>Post</code> and stop re-checking every field. TypeScript cannot see the network. The parser is how the static type gets reattached to a real payload.</p>
<p>A cast (<code>as Post</code>) is not a parser. It silences the compiler and leaves the runtime value untouched. If the payload is <code>{ title: 12 }</code> or <code>null</code>, the cast still succeeds and the failure moves to the first <code>post.title.toUpperCase()</code>.</p>
<p>I keep parsers small and boring: reject <code>null</code>, reject arrays (because <code>typeof [] === &quot;object&quot;</code>), check each field, return a fresh object. Returning a fresh object means I do not leak extra fields I never declared. A schema library is fine when I already depend on one. The habit is the boundary, not the brand of the checker.</p>
</section>

New
</h2>
<p><strong>Right approach: unknown at the edge, a parser that returns Post, trusted types after that</strong></p>
<p><strong>Best case.</strong> Malformed JSON, <code>null</code>, arrays, and missing fields fail in <code>parsePost</code> with a message that names the field. Callers of <code>loadPost</code> see <code>Post</code> only.</p>
<p><strong>Worst case.</strong> A parser that checks one field and casts the rest. I would rather check two fields honestly than pretend a single <code>typeof</code> covers the model.</p>
<p>After: the only <code>Post</code> in the app is the object the parser built.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use a concrete type for values I created in trusted code. Use <code>unknown</code> for anything that crossed a process, a storage boundary, or a JSON parser. Cast only when a type is already proved and the compiler cannot see it, and even then I keep the cast next to the proof. <code>any</code> remains the option I do not take on models.</p>
<div class="when">
<div class="when-row"><span>A value this function just built</span><span class="when-choice">concrete type</span></div>
<div class="when-row"><span>JSON, storage, or a request body</span><span class="when-choice">unknown plus a parser</span></div>
<div class="when-row"><span>A type the compiler already proved</span><span class="when-choice">a narrow cast beside the proof</span></div>
<div class="when-row"><span>A core model I am tempted to silence</span><span class="when-choice">replace any</span></div>
</div>
</section>
