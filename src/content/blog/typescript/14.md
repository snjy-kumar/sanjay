What it is
</h2>
<p>Most of the TypeScript I actually keep came from a bug in a project I cared about, not from a tour of the handbook. Courses gave me names. The bug gave me a reason to use one feature the next time.</p>
<p>The bug was an id. I rendered a profile from an API and assumed <code>userId</code> was a string. Sometimes it was a number. A React key warning and a path built with string concatenation disagreed with each other. The cast <code>as string</code> made the file compile and left the number in place, so the path became something the router did not know.</p>
<p>The repair was not a framework trick. It was one function, <code>asId</code>, that accepts <code>unknown</code> and returns a string only after a <code>typeof</code> check. Numbers are stringified on purpose. Anything else throws at the boundary, where I can show a failure instead of a broken link.</p>
<p>The loop I use now is small. I hit a bug. I ask which type lie allowed it. I learn the smallest feature that removes that lie. I keep the helper. Here the feature was a boundary parser plus a narrow return type. Next time an id shows up, I call <code>asId</code> instead of casting.</p>

New
</h2>
<p><strong>Right approach: name the bug, then write the smallest check that makes it unrepresentable</strong></p>
<p><strong>Best case.</strong> <code>asId(12)</code> and <code>asId(&quot;12&quot;)</code> both return a string. <code>asId(null)</code>, <code>asId(&quot;&quot;)</code>, and <code>asId(Number.NaN)</code> throw before navigation.</p>
<p><strong>Worst case.</strong> A helper that silently turns every unknown into <code>&quot;&quot;</code>. The type is <code>string</code>, the screen looks empty, and I have hidden the same bug behind a default.</p>
<p>After: only a finite number or a non-empty string becomes an id. The path is built from the return value alone.</p>

When to use which
</h2>
<p>Learn a feature when a real failure names it. A cast is a last step beside a proof, not the proof. A boundary helper is worth keeping when a second call site would copy the same <code>typeof</code> ladder. I do not add a generic, a mapped type, or a schema dependency for a check this small.</p>
<div class="when">
<div class="when-row"><span>The value is already the type I think</span><span class="when-choice">use it directly</span></div>
<div class="when-row"><span>The bug was a cast over a boundary</span><span class="when-choice">a parser with a narrow return</span></div>
<div class="when-row"><span>Two call sites repeat the check</span><span class="when-choice">keep the helper</span></div>
<div class="when-row"><span>I am studying a feature with no bug yet</span><span class="when-choice">wait for a real failure</span></div>
</div>
</section>
