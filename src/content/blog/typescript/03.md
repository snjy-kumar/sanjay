<section class="section" id="what-it-is">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><circle cx="7" cy="7" r="4.75"/><path d="M7 6.35v3.45"/><path d="M7 4.4v.02" stroke-width="1.8"/></svg>
What it is
</h2>
<p>If a value has four real states, <code>string</code> says it has infinitely many. Typos type-check. A status of <code>"sucess"</code> sails through, and the UI has a branch for a state that does not exist in the product plus no branch for one that does.</p>
<p>A union lists the members you actually handle: <code>"idle" | "loading" | "error" | "success"</code>. Assigning anything else is an error. A <code>switch</code> that returns on each member starts failing the compile when a member is added and a case is forgotten, which is the compiler complaining with better memory than yours. Autocomplete offers the real set instead of every string you have typed this year.</p>
<p>That is not an advanced trick. It is how you stop describing a finite fact as an open primitive. When each state also carries different data — a message only on error, a post only on success — the same idea gets stricter as a discriminated union, so those fields cannot appear together by accident. Start with the literal union if the payload is shared; split the object if the fields are not.</p>
<p>A fetch panel on a personal project shows one of four labels: waiting, loading, failed, done. The first version stored <code>status: string</code> and optional <code>data</code> and <code>error</code> on the same object. A typo in a setter left the panel blank. Another path set both <code>data</code> and <code>error</code>, and the UI rendered a successful post with an error banner under it.</p>

Old
</h2>
<p><strong>Wrong approach: <code>string</code> for a finite set</strong></p>
<p><strong>Best case.</strong> Every writer of the field is a constant you control, the tests spell the same four words, and nobody typos them. The bug is latent, not visible.</p>

New
</h2>
<p><strong>Right approach: a union of the real options</strong></p>
<p><strong>Best case.</strong> New states do not compile until every switch handles them. Call sites get autocomplete. Impossible combinations are not representable, so the blank-screen class of bugs moves to compile time.</p>
<p><strong>Worst case.</strong> You union together states that are not exhaustive in the real system — the server can still send <code>"queued"</code> — and then a parser you do not have throws only at runtime. A union models what you decided to accept. Untrusted strings still need a parse step into that union, or the outside world will hand you a value the type pretends cannot exist.</p>
<p>After: the status is a union, and the text helper has nowhere to forget a member.</p>

<section class="section" id="when">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Search for fields whose comments list the allowed strings, and replace the comment with a union. Switch on that union without a catch-all string compare; put <code>assertNever</code> in the default so a new member fails the build. Parse external input into the union once. If two fields cannot be true together, split them into separate union members instead of optional properties on one object. Do not use a union for genuinely open text.</p>
<div class="when">
<div class="when-row"><span>A finite set of states</span><span class="when-choice">union</span></div>
<div class="when-row"><span>Fields that cannot be true together</span><span class="when-choice">separate members</span></div>
<div class="when-row"><span>An untrusted string from outside</span><span class="when-choice">parse into the union</span></div>
<div class="when-row"><span>Genuinely open text</span><span class="when-choice">string</span></div>
</div>
</section>
