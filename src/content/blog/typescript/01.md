What it is
</h2>
<p>A <code>string</code>, a <code>number</code>, and a <code>boolean</code> are real types. They are also very wide. Treating them as labels — write the primitive, move on — lets values through that look typed and still mean the wrong thing at runtime.</p>
<p>Three failures show up as soon as a form or an API is involved. An “empty” text field is still a <code>string</code>: <code>""</code>. An id that looks numeric is often a string from JSON (<code>"42"</code>), and the reverse happens too. And <code>true</code> is not <code>"true"</code>. <code>Boolean("false")</code> is <code>true</code>, because any non-empty string is truthy. <code>Number("n/a")</code> is <code>NaN</code>, and <code>NaN</code> is a <code>number</code>, so a typed age field accepts it. An empty numeric field is a different trap: <code>Number("")</code> is <code>0</code>, which also type-checks and is still the wrong age.</p>
<p>The correction is to make the type say what the value is allowed to be, then refuse everything else at the boundary. A status that is only ever draft or published should be <code>"draft" | "published"</code>, not <code>string</code>. A value that can be empty should say which kind of empty is legal: a blank string, <code>null</code>, or a missing property are different states. Checks such as <code>typeof</code> and <code>Number.isNaN</code> belong where untrusted input enters, not three components later.</p>
<p>A small publishing screen in a personal project: title input, a status control, an age or “years using the tool” number, and an “active” flag that one backend sends as a boolean and another sends as the strings <code>"true"</code> and <code>"false"</code>. The loose model compiles. The published record then has status <code>"yes"</code>, an id you cannot safely concatenate, and an age of <code>NaN</code> that renders as blank in one view and breaks a sort in another.</p>

<p><strong>Best case.</strong> A one-off script whose fields really are free text, a count you already sanitized, and a boolean you set yourself in the same function. The wide types happen to match the data because nothing untrusted touches them.</p>

New

<p><strong>Right approach: precise types and a boundary parse</strong></p>
<p><strong>Best case.</strong> Illegal status strings do not assign. <code>parseAge</code> throws on <code>NaN</code> and on numeric strings you forgot to convert. <code>parseActive</code> accepts both JSON booleans and the legacy string form, and nothing else. Call sites after the parse use <code>User</code> without guessing.</p>
<p><strong>Worst case.</strong> You invent a giant union for a field that really is open-ended prose, or you throw on empty drafts that the product allows. Precision still has to match the domain. A closed union for a closed set is the win; a closed union for a comment body is noise.</p>
<p>After: the save path accepts unknown form state and returns a <code>User</code> only after each field has been read deliberately.</p>

<section class="section" id="when">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Keep primitives where the set is actually open: a title, a free-text bio, a count you computed locally. As soon as a field has a known shape — a lifecycle, an enum from the API, a flag that crosses a JSON boundary — name that shape. Put the parsers next to the model, call them once where data enters, and let the rest of the app take the parsed type. Prefer <code>Number.isNaN</code> or <code>Number.isFinite</code> over a truthiness check for numbers. Never coerce flags with <code>Boolean(string)</code>. If empty is legal, decide whether you mean <code>""</code>, <code>null</code>, or an optional property, and type only that.</p>
<div class="when">
<div class="when-row"><span>Free text, a local count, or a boolean you set yourself</span><span class="when-choice">primitive</span></div>
<div class="when-row"><span>A closed lifecycle or API enum</span><span class="when-choice">literal union</span></div>
<div class="when-row"><span>A flag or number crossing JSON</span><span class="when-choice">parse at the edge</span></div>
<div class="when-row"><span>Empty that the product allows</span><span class="when-choice">name which empty</span></div>
</div>
</section>
