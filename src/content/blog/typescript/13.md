What it is
</h2>
<p>Mapped types clicked when I stopped keeping two lists of feature flags. I had an object, <code>darkMode</code>, <code>betaSearch</code>, <code>newEditor</code>, and a hand-written type I updated only when I remembered. The object grew a key. The type did not. A helper that indexed the type still compiled and then returned <code>undefined</code> at runtime.</p>
<p>A mapped type writes one rule for every key in a union: <code>{ [K in FlagName]: boolean }</code>. <code>FlagName</code> is the single list. <code>Flags</code> requires each of those keys to be a boolean. Add a flag to the union and every <code>Flags</code> object must grow the same key.</p>
<p><code>satisfies Flags</code> checks that the object matches <code>Flags</code> without widening the variable to the mapped type and throwing away the literal keys. A missing key is an error. An extra key is an error. A string where a boolean belongs is an error. I can still pass <code>flags.darkMode</code> around as <code>boolean</code>.</p>
<p>I use the same pattern for route tables and permission maps: one key union, one value rule. I do not reach for a mapped type when the fields have unrelated shapes. That is just an interface.</p>
</section>

New
</h2>
<p><strong>Right approach: map one key union to a value rule, and check the object with satisfies</strong></p>
<p><strong>Best case.</strong> Adding <code>&quot;newEditor&quot;</code> to <code>FlagName</code> and forgetting the object is a compile error. <code>isOn</code> cannot be called with a random string.</p>
<p><strong>Worst case.</strong> A mapped type over a huge key set I do not control, producing an object I cannot realistically fill in. If the set is open-ended, a <code>Map</code> or a record with an index signature is the honest model, with a parser in front of it.</p>
<p>After: every flag name has a boolean, and <code>satisfies</code> keeps the object literal honest.</p>

<section class="section" id="when">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Write an interface when each field has its own type. Use a mapped type when every key in a known set follows one rule. Prefer <code>satisfies</code> over a wide annotation when I want both the check and the inferred literal. Derive with <code>keyof typeof</code> when the object is authored first and the union should follow it.</p>
<div class="when">
<div class="when-row"><span>Fields with unrelated shapes</span><span class="when-choice">interface or type alias</span></div>
<div class="when-row"><span>Every key shares one value rule</span><span class="when-choice">mapped type</span></div>
<div class="when-row"><span>Author the object first</span><span class="when-choice">keyof typeof</span></div>
<div class="when-row"><span>Author the allowed keys first</span><span class="when-choice">union plus satisfies</span></div>
</div>
</section>
