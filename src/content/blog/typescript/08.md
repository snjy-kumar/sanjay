What it is
</h2>
<p>Type narrowing is the moment TypeScript started feeling helpful on my personal projects, rather than merely strict. I used to write <code>if (value)</code> and expect the compiler to inherit my confidence. It will not. It only follows checks it can see.</p>
<p>After <code>typeof value === &quot;string&quot;</code>, <code>value instanceof Error</code>, <code>value === null</code>, or a predicate such as <code>isPost(value)</code>, the type inside that branch gets smaller. Step outside the branch and the wide type comes back. The narrow type also does not cross an ordinary function call. If a helper should narrow for its caller, the return type has to say <code>value is Post</code>.</p>
<p>Truthiness is a sloppy teacher. On <code>string | null</code>, <code>if (x)</code> treats <code>&quot;&quot;</code> the same as <code>null</code>. On a number, <code>if (n)</code> treats <code>0</code> as missing. I write the comparison I mean: <code>x === null</code>, <code>typeof x === &quot;string&quot;</code>, or <code>typeof n === &quot;number&quot; &amp;&amp; Number.isFinite(n)</code>.</p>
<p>On a reading screen I validate once where the payload enters. After that function returns a <code>Post</code>, the rest of the path uses <code>post.title</code> without another cast. The everyday skill is an honest <code>if</code>, not a generic.</p>

New
</h2>
<p><strong>Right approach: compare against null, or name a predicate, and let the branch carry the type</strong></p>
<p><strong>Best case.</strong> The compiler and the runtime agree. After the guard, <code>x.length</code> and <code>value.title</code> type-check with no cast.</p>
<p><strong>Worst case.</strong> A predicate that returns <code>true</code> without checking every field the type requires. Narrowing will trust the signature, so a sloppy predicate is a lie with good syntax.</p>
<p>After: <code>&quot;&quot;</code> still has length 0, and only <code>null</code> takes the early return.</p>

<h2>

When to use which
</h2>
<p>Use a truthiness check only when every falsy value truly means “absent” for that field. Prefer an explicit comparison when <code>&quot;&quot;</code>, <code>0</code>, or <code>false</code> is data. Use a type predicate when the same shape test appears in more than one function. Leave a value alone when it is already the right type and no untrusted input touched it.</p>
<div class="when">
<div class="when-row"><span>Every falsy value means absent</span><span class="when-choice">truthiness check</span></div>
<div class="when-row"><span>Empty string or zero is real data</span><span class="when-choice">explicit comparison</span></div>
<div class="when-row"><span>The same shape test is reused</span><span class="when-choice">type predicate</span></div>
<div class="when-row"><span>The value is already the right type</span><span class="when-choice">no extra guard</span></div>
</div>
