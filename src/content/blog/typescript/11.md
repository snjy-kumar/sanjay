What it is
</h2>
<p>My async screens used to be one object with optional fields: a status string, maybe <code>data</code>, maybe <code>error</code>. TypeScript allowed every combination. A direct <code>data.title</code> is a compile error under strict null checks, so I papered over it with <code>data!</code>. The screen still crashed when <code>status</code> was <code>&quot;error&quot;</code> and <code>data</code> was missing.</p>
<p>A discriminated union is a union of objects that share a literal field, the discriminant. Here that field is <code>status</code>. When I check <code>result.status === &quot;success&quot;</code>, TypeScript narrows the whole object, and <code>data</code> exists only in that branch. In the error branch, <code>data</code> is not there to read.</p>
<p>Optional fields cannot say “these two states cannot happen together.” <code>{ data?: Post; error?: string }</code> allows both, neither, or either. The bug is representable. The union makes the impossible state unrepresentable, which is the point.</p>
<p>I use this for fetch state, for a short wizard (step tags instead of a pile of booleans), and for any result where the payload depends on the outcome. A <code>switch</code> with a <code>never</code> default tells me when I add a status and forget a branch.</p>
</section>

New

<p><strong>Right approach: one object per state, selected by a shared literal tag</strong></p>
<p><strong>Best case.</strong> Success is the only place <code>data</code> exists. Adding <code>&quot;empty&quot;</code> without updating <code>label</code> is a compile error at the <code>never</code> check.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use optional fields when the pieces really are independent, such as a profile whose bio and website can each be missing. Use a discriminated union when the fields are mutually exclusive. Keep the tag a string-literal union, not <code>string</code>. Put the payload on the variant that owns it, not on every variant as optional.</p>
<div class="when">
<div class="when-row"><span>Independent optional fields</span><span class="when-choice">ordinary optionals</span></div>
<div class="when-row"><span>States that cannot overlap</span><span class="when-choice">discriminated union</span></div>
<div class="when-row"><span>A new status might be added later</span><span class="when-choice">exhaustive switch</span></div>
<div class="when-row"><span>The tag is free text from a draft</span><span class="when-choice">parse it before the union</span></div>
</div>
