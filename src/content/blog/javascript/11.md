<h2>

What it is
</h2>
<p>I passed a method as a callback and it lost the object it belonged to. <code>user.greet()</code> sets <code>this</code> to <code>user</code> because the call has a receiver. <code>const greet = user.greet; greet()</code> has no receiver. In a module, which is strict mode, <code>this</code> is <code>undefined</code> and <code>this.name</code> throws. In a classic sloppy script, <code>this</code> becomes the global object instead. Either way, the method is no longer talking about <code>user</code>.</p>
<p>Arrow functions do not get their own <code>this</code>. They capture the <code>this</code> of the surrounding scope. That is useful for a callback written inside a method, and useless if I wanted dynamic <code>this</code>. I use a normal method when the receiver should depend on the call, and an arrow when the function should ignore how it is called.</p>
<p>When I hand a method to <code>addEventListener</code> or <code>setTimeout</code>, I do not pass <code>user.greet</code> bare. I pass <code>() =&gt; user.greet()</code>, or <code>user.greet.bind(user)</code>. The wrapper makes the receiver obvious at the handoff.</p>
<p><code>this</code> is a call-site rule, not a definition-site rule. I read the call, not the place where the function was written.</p>

New
</h2>
<p><strong>Right approach: call the method on its object inside the callback</strong></p>
<p><strong>Best case.</strong> <code>user.greet()</code> has a receiver even though the listener’s own <code>this</code> is the button. A reader sees the object at the call.</p>
<p><strong>Worst case.</strong> <code>bind</code> on every render creating a new function and stacking listeners if I also forget to remove the old one. The wrapper has to be the function I can unsubscribe.</p>
<p>After: the event listener’s only job is to perform the method call I can see.</p>

<section class="section" id="when">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use a method call with a receiver when you mean that object. Use an arrow to capture the surrounding <code>this</code>. Use <code>bind</code> or a wrapper when you must pass the function away. Do not read <code>this</code> in a plain function and expect the object you defined it next to.</p>
<div class="when">
<div class="when-row"><span>obj.method()</span><span class="when-choice">this is obj</span></div>
<div class="when-row"><span>A callback that should ignore its caller</span><span class="when-choice">arrow, or a wrapper that calls the method</span></div>
<div class="when-row"><span>A method passed to a listener</span><span class="when-choice">wrap or bind</span></div>
<div class="when-row"><span>A module top-level this</span><span class="when-choice">undefined, because modules are strict</span></div>
</div>
</section>
