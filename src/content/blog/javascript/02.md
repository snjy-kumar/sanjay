What it is
</h2>
<p><code>0 == false</code> passed a condition in a personal project and still sent the wrong empty-state message. I had treated a numeric count and a boolean flag as interchangeable. JavaScript was following its abstract-equality rules. My assumption was the bug.</p>
<p><code>==</code> converts the operands before comparing. <code>===</code> checks type and value, with the one famous exception that <code>NaN === NaN</code> is false, so I use <code>Number.isNaN</code> for that case. <code>null == undefined</code> is true, and <code>null === undefined</code> is false. That single difference is why a sloppy null check sometimes “works.”</p>
<p>I reach for <code>===</code> and <code>!==</code> first. If I intentionally compare across types, I convert in a separate line: <code>Number(flag)</code> or <code>count === 0</code>. The next reader can see the rule. Hidden coercion cannot be reviewed.</p>
<p>Strict equality is not a magic fix for every bug. It will not validate a payload. It will stop a <code>0</code> from impersonating <code>false</code> in a condition I meant to be numeric.</p>
</section>

New

<p><strong>Right approach: compare with ===, and convert on its own line when a conversion is real</strong></p>
<p><strong>Best case.</strong> <code>render(0)</code> returns <code>&quot;empty&quot;</code> only because the condition says zero. <code>render(false)</code> is not silently treated as a count.</p>
<p><strong>Worst case.</strong> Using <code>===</code> and then forgetting <code>NaN</code>, or comparing two objects by identity when I meant their fields. Strict equality does not deep-compare.</p>
<p>After: zero is checked as a number. The flag is checked as a boolean.</p>

<h2>

When to use which
</h2>
<p>Use <code>===</code> and <code>!==</code> for ordinary checks. Use <code>Object.is</code> when you care that <code>NaN</code> equals <code>NaN</code> or that <code>-0</code> and <code>0</code> differ. Write a conversion yourself when the domain really crosses types. I do not use <code>==</code> to “just handle null and undefined”; I write <code>value == null</code> only when I mean both, and I know that this one coercion is the reason.</p>
<div class="when">
<div class="when-row"><span>Two values that should share a type</span><span class="when-choice">===</span></div>
<div class="when-row"><span>NaN</span><span class="when-choice">Number.isNaN</span></div>
<div class="when-row"><span>null or undefined on purpose</span><span class="when-choice">value == null, and a comment if it is surprising</span></div>
<div class="when-row"><span>A number coming from an input string</span><span class="when-choice">convert, then ===</span></div>
</div>
</section>
