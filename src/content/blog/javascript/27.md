What it is
</h2>
<p>I serialized a growing draft on every keystroke and then blamed the UI toolkit for the typing lag. <code>localStorage</code> is synchronous. <code>setItem</code> and <code>getItem</code> run on the main thread, and <code>JSON.stringify</code> of a large object adds more work before the write. A preference toggle is fine. A transcript written per character is not.</p>
<p>Storage can also throw. The quota can be full. Some private-browsing modes refuse access. A bare <code>setItem</code> then becomes an exception in the middle of an input handler, which feels like a broken key rather than a full disk. I catch it and show a small warning.</p>
<p>I debounce the write, keep the payload to the fields I will actually restore, and treat storage as a cache. The page still works if the write fails. I do not put secrets in <code>localStorage</code>. It is readable by any script on the origin.</p>
<p>Synchronous APIs deserve a budget. I persist what helps the next visit, not every intermediate object, and I never do it on the unfiltered input event.</p>
</section>

New
</h2>
<p><strong>Right approach: debounce a small payload and catch storage failures</strong></p>
<p><strong>Best case.</strong> The keystroke returns immediately. One write happens after a pause. A full quota shows a warning. The in-memory draft remains the source of truth.</p>
<p><strong>Worst case.</strong> A debounce that never flushes on page hide, so the last pause is lost. I also save once on <code>visibilitychange</code> or <code>pagehide</code> if the draft matters.</p>
<p>After: stringify and <code>setItem</code> sit inside the timer, inside <code>try</code>.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use <code>localStorage</code> for small preferences and drafts you can afford to lose or to rewrite. Debounce bursts. Catch exceptions. Keep the in-memory value authoritative. Do not store secrets, and do not write large structures on the input path.</p>
<div class="when">
<div class="when-row"><span>A theme or a small draft</span><span class="when-choice">localStorage, debounced if it follows typing</span></div>
<div class="when-row"><span>A write that might exceed quota</span><span class="when-choice">try/catch and a warning</span></div>
<div class="when-row"><span>Data another tab must see immediately</span><span class="when-choice">storage event, still small</span></div>
<div class="when-row"><span>A secret or a large log</span><span class="when-choice">not localStorage</span></div>
</div>
</section>
