What it is
</h2>
<p>I rendered a preview with <code>innerHTML</code> and forgot the string was not mine to trust. <code>innerHTML</code> parses HTML. If the string comes from a person, a query parameter, or an API, assigning it can create elements and handlers I never wrote. That is a cross-site scripting bug, not a styling shortcut.</p>
<p><code>textContent</code> writes text. Tags show up as characters. Nothing is parsed, nothing runs. That is the right tool for a comment, a title, or an error message. When I truly need markup, I build nodes with <code>document.createElement</code> and set <code>textContent</code> on them, or I sanitize with a library I have chosen and keep the trust decision in one function.</p>
<p>I do not “fix” untrusted HTML by stripping a few characters myself. Partial filters miss encodings and attributes. The safe default is to not parse. The code should make the trust boundary obvious: this string is text, or this string has been sanitized in this named function.</p>
<p>The safest HTML string is often no HTML string. A preview of what someone typed is text until I have a real reason for it to be markup.</p>
</section>

New

<p><strong>Right approach: put untrusted strings in textContent, and build real elements when you need structure</strong></p>
<p><strong>Best case.</strong> Comments render as text. A list of titles is a set of elements I created, each with <code>textContent</code>. There is no HTML string to get wrong.</p>

<p>After: the comment is text. A structured row is a node I created, and its title is still text.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use <code>textContent</code> for text. Use <code>createElement</code> when you need structure. Use <code>innerHTML</code> only for markup you trust, ideally a constant with no outside interpolation. Do not build that string by concatenation from a person, a URL, or a response field.</p>
<div class="when">
<div class="when-row"><span>A comment, name, or error</span><span class="when-choice">textContent</span></div>
<div class="when-row"><span>A list or a card you design</span><span class="when-choice">createElement</span></div>
<div class="when-row"><span>A constant snippet you wrote</span><span class="when-choice">innerHTML is possible, text is still safer</span></div>
<div class="when-row"><span>HTML from a person or an API</span><span class="when-choice">do not parse it here</span></div>
</div>
