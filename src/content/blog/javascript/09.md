What it is
</h2>
<p>A cache in a personal project used a plain object. A lookup for <code>constructor</code> behaved unlike the other keys. I had not stored <code>constructor</code>. The object still had one, because it inherits from <code>Object.prototype</code>. A truthy check treated that inherited function as a cache hit.</p>
<p>Plain objects are a good record: a known set of fields, usually identifiers, read with dot or bracket access. They are a poor dictionary. Keys are strings or symbols (numbers get stringified), <code>&quot;__proto__&quot;</code> is a special assignment hazard, and <code>in</code> / truthiness can see the prototype chain. <code>Object.hasOwn</code> tells me about own properties only.</p>
<p>A <code>Map</code> keeps arbitrary keys, including objects, and does not consult a prototype for <code>get</code>. <code>has</code> is the existence check, so a stored <code>0</code> or <code>&quot;&quot;</code> is still a hit. <code>size</code> is the count. Iteration is the insertion order of entries, not a mix of inherited names.</p>
<p>I use objects for shaped data and maps for caches, counts, and anything whose keys are data rather than a schema. If the key set is fixed, an object is still the clearer type.</p>
</section>

New
</h2>
<p><strong>Right approach: a Map with has and get for arbitrary keys</strong></p>
<p><strong>Best case.</strong> <code>constructor</code> is an ordinary key. <code>has</code> distinguishes missing from a stored falsy value. <code>size</code> is trustworthy.</p>
<p><strong>Worst case.</strong> A <code>Map</code> for a record with three known fields. Call sites lose <code>note.title</code> autocomplete and dot access, and JSON does not round-trip a Map. That data wanted an object.</p>
<p>After: the cache does not inherit keys, and presence is <code>has</code>.</p>

When to use which
</h2>
<p>Use an object for a record with known fields. Use a <code>Map</code> for a runtime dictionary, especially when keys are untrusted, non-strings, or allowed to be names like <code>constructor</code>. Check presence with <code>Object.hasOwn</code> on objects and <code>map.has</code> on maps, not with truthiness.</p>
<div class="when">
<div class="when-row"><span>Known fields on a record</span><span class="when-choice">object</span></div>
<div class="when-row"><span>Arbitrary or untrusted keys</span><span class="when-choice">Map</span></div>
<div class="when-row"><span>A stored value may be falsy</span><span class="when-choice">Map.has, or Object.hasOwn</span></div>
<div class="when-row"><span>You need JSON as the storage format</span><span class="when-choice">object, after you control the keys</span></div>
</div>
