<section class="section" id="what-it-is">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><circle cx="7" cy="7" r="4.75"/><path d="M7 6.35v3.45"/><path d="M7 4.4v.02" stroke-width="1.8"/></svg>
What it is
</h2>
<p>Fast typing made an older search response overwrite the newer result. Each request was valid when it started. The screen had moved on. The bug was lifetime, not the URL.</p>
<p><code>AbortController</code> creates a signal I pass to <code>fetch</code>. Calling <code>abort()</code> rejects the fetch with a <code>DOMException</code> whose <code>name</code> is <code>&quot;AbortError&quot;</code>. I must not show that as a failure toast. I also check <code>response.ok</code> so a 500 is a real error. I encode the query with <code>encodeURIComponent</code> so a search for <code>a&amp;b</code> cannot break the query string.</p>
<p>The controller has to be the one for the current query. When the query changes, I abort the previous controller, then create a new one. If I abort after overwriting the variable, I lose the handle and the old request keeps running. I keep <code>controller</code> outside the request function and abort it at the start of the next search.</p>
<p>Async cleanup is part of correctness. A response the screen no longer wants should not paint. Abort is how I say that to <code>fetch</code>.</p>
</section>

New
</h2>
<p><strong>Right approach: one controller for the current query, abort it when the query is replaced, ignore AbortError</strong></p>
<p><strong>Best case.</strong> Replacing <code>q</code> cancels the previous body. The rendered JSON belongs to the latest request that was allowed to finish. Bad HTTP statuses still reach <code>showError</code>.</p>
<p><strong>Worst case.</strong> Aborting and then still applying a cached promise from somewhere that did not take the signal. Anything that fetches for this screen has to see the same signal, or I drop results with a request id.</p>
<p>After: starting a search cancels the previous one before <code>fetch</code> is called.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Create a controller per in-flight action. Pass <code>signal</code> into every <code>fetch</code> that belongs to it. Abort when the query, the page, or the component is replaced. Ignore <code>AbortError</code>. Do not ignore other errors. Encode query values.</p>
<div class="when">
<div class="when-row"><span>A search box that can overlap</span><span class="when-choice">abort the previous request</span></div>
<div class="when-row"><span>Leaving the page</span><span class="when-choice">abort in the teardown</span></div>
<div class="when-row"><span>The rejection is AbortError</span><span class="when-choice">do not show it as failure</span></div>
<div class="when-row"><span>The status is not ok</span><span class="when-choice">surface that error</span></div>
</div>
