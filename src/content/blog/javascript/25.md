What it is
</h2>
<p>A lazy loader I wrote with scroll math missed items during a fast scroll. I was comparing <code>scrollY</code>, <code>innerHeight</code>, and <code>offsetTop</code> on every scroll event, and the layout I measured was already stale. The browser already knows when an element crosses the viewport. <code>IntersectionObserver</code> reports that.</p>
<p>I observe a sentinel, or each image, and the callback receives entries. <code>entry.isIntersecting</code> is the bit I branch on. The callback runs when intersection changes, not on every scroll pixel. <code>rootMargin</code> can start the load a little before the element is visible. <code>threshold</code> decides how much of the element must be visible.</p>
<p>Observers outlive a casual scroll listener if I forget them. When the feature leaves the page, or the sentinel is removed for good, I call <code>observer.disconnect()</code> or <code>unobserve</code>. A loader that should fire once unobserves that target inside the callback so it does not keep loading.</p>
<p>If the platform can report the fact, I stop reconstructing the fact from scroll coordinates. Scroll listeners remain for things that are actually about scroll position, and even then I keep them thin.</p>

Old

<p><strong>Wrong approach: compare scroll offsets on every scroll event to decide visibility</strong></p>
<p><strong>Best case.</strong> A document that does not change height except when you load more, and a listener you actually remove. The math can be made correct. It is still more code than the fact required.</p>
<p><strong>Worst case.</strong> Fast scrolls skip the exact equality, a nested scroller is ignored because you listened to <code>window</code>, or the listener stays after the page is gone.</p>

New
</h2>
<p><strong>Right approach: observe a sentinel and disconnect when the feature is done</strong></p>
<p><strong>Best case.</strong> The callback runs on intersection changes. Nested scrollers can be the <code>root</code>. Cleanup is <code>disconnect</code>. A one-shot image unobserves itself after loading.</p>
<p><strong>Worst case.</strong> Forgetting <code>disconnect</code>, or loading more every time the sentinel stays intersecting, so I append forever without a guard. I set a loading flag and stop observing when there is no next page.</p>
<p>After: the browser reports the intersection, and the caller can disconnect the returned observer.</p>

When to use which
</h2>
<p>Use <code>IntersectionObserver</code> for lazy loading, reveal effects, and infinite-scroll sentinels. Pass a <code>root</code> when the scroller is not the viewport. Disconnect or unobserve on teardown. Keep a flag so a still-visible sentinel does not fire overlapping loads.</p>
<div class="when">
<div class="when-row"><span>Is this element in view?</span><span class="when-choice">IntersectionObserver</span></div>
<div class="when-row"><span>Which scroll offset is the toolbar?</span><span class="when-choice">scroll, kept thin</span></div>
<div class="when-row"><span>Load once when first shown</span><span class="when-choice">unobserve after the load</span></div>
<div class="when-row"><span>The UI that created the observer is gone</span><span class="when-choice">disconnect</span></div>
</div>
