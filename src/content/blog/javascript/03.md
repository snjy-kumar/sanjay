What it is
</h2>
<p>I replaced a saved count of <code>0</code> with a default label. The line was <code>count || &quot;No items&quot;</code>. Zero was a valid result. The fallback treated it as absence, and the dashboard showed a dash for a measurement that had succeeded.</p>
<p>JavaScript’s falsy values are <code>false</code>, <code>0</code>, <code>-0</code>, <code>0n</code>, <code>&quot;&quot;</code>, <code>null</code>, <code>undefined</code>, and <code>NaN</code>. Everything else is truthy, including <code>&quot;0&quot;</code>, <code>&quot;false&quot;</code>, and <code>[]</code>. A truthiness check is a real tool when every one of those values should take the same branch. It is the wrong tool when zero or an empty string is data.</p>
<p><code>??</code> only substitutes for <code>null</code> and <code>undefined</code>. <code>0 ?? &quot;No items&quot;</code> is <code>0</code>. <code>&quot;&quot; ?? &quot;No items&quot;</code> is <code>&quot;&quot;</code>. That is the operator I want for a count or a title that may be blank on purpose.</p>
<p>Before I write <code>if (value)</code> or <code>value || fallback</code>, I list whether <code>false</code>, <code>0</code>, and <code>&quot;&quot;</code> are real in this feature. If any of them is real, I name the missing case instead of borrowing truthiness.</p>
</section>

Old
</h2>
<p><strong>Wrong approach: use || or if (value) as a stand-in for missing</strong></p>
<p><strong>Best case.</strong> The only absent values you store are <code>null</code> or <code>undefined</code>, and <code>0</code> cannot occur. Then <code>||</code> agrees with the domain by accident.</p>
<p><strong>Worst case.</strong> A zero count, a false opt-out, or a blank optional string is replaced. The UI hides a successful empty result.</p>
<p>Before: <code>||</code> collapses every falsy count into one label.</p>

New
</h2>
<p><strong>Right approach: use ?? when only null and undefined mean missing</strong></p>
<p><strong>Best case.</strong> <code>formatCount(0)</code> is <code>0</code>. <code>formatCount(null)</code> and <code>formatCount(undefined)</code> are the sentence. An empty string can be handled on its own line if it is a third state.</p>
<p><strong>Worst case.</strong> <code>??</code> keeping a value I actually wanted to reject, such as <code>NaN</code>. <code>NaN ?? &quot;No items&quot;</code> is <code>NaN</code>, because <code>NaN</code> is not nullish. I still check <code>Number.isFinite</code> when the domain is a real number.</p>
<p>After: the fallback applies to absence, not to zero.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use <code>||</code> when every falsy value should fall through, such as a string that must be non-empty. Use <code>??</code> when <code>0</code>, <code>false</code>, or <code>&quot;&quot;</code> must survive. Use an explicit comparison when more than one of those values needs its own branch.</p>
<div class="when">
<div class="when-row"><span>Only non-empty strings are useful</span><span class="when-choice">||</span></div>
<div class="when-row"><span>Zero or false is valid</span><span class="when-choice">??</span></div>
<div class="when-row"><span>null and undefined both mean missing</span><span class="when-choice">??</span></div>
<div class="when-row"><span>NaN should not pass</span><span class="when-choice">Number.isFinite</span></div>
</div>
</section>
