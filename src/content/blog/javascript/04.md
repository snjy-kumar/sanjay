What it is
</h2>
<p>A guard in a personal project said an API payload was an object when it was <code>null</code>. <code>typeof null</code> is the string <code>&quot;object&quot;</code>. That result is historical, from the original representation of null, and it is not going to change. My check trusted it, and <code>payload.title</code> threw once loading finished and the value was actually null.</p>
<p><code>typeof</code> is still useful. <code>typeof &quot;&quot;</code> is <code>&quot;string&quot;</code>, <code>typeof undefined</code> is <code>&quot;undefined&quot;</code>, and <code>typeof function () {}</code> is <code>&quot;function&quot;</code>. It is not a complete object test. Arrays are objects. <code>null</code> pretends to be one. Dates are objects. I need a check that names the case I accept.</p>
<p>I test <code>value === null</code> or <code>value == null</code> (when I also mean undefined) before <code>typeof value === &quot;object&quot;</code>. Then I reject arrays with <code>Array.isArray</code> if a list is not a valid payload. The order matters: the null check has to win first, because <code>typeof null === &quot;object&quot;</code> is true.</p>
<p>The honest fix for a historical quirk is to name the case. I do not build a clever wrapper to hide <code>typeof</code> from myself. I write the null check where the value enters.</p>

New

<p><strong>Right approach: exclude null, then test the object, then test the field</strong></p>
<p><strong>Best case.</strong> <code>titleOf(null)</code>, <code>titleOf(undefined)</code>, and <code>titleOf([])</code> return the fallback. A real <code>{ title: &quot;Notes&quot; }</code> returns the string.</p>
<p><strong>Worst case.</strong> A guard so long that I skip it on the next field. I would rather check <code>title</code> with <code>typeof</code> than assume every remaining property is a string.</p>
<p>After: null cannot reach the property read.</p>

<h2>

When to use which
</h2>
<p>Use <code>typeof</code> for strings, numbers, booleans, functions, and undefined. Do not use it alone for objects. Put <code>value !== null</code> in the same condition, and decide explicitly whether arrays, dates, or class instances count as success.</p>
<div class="when">
<div class="when-row"><span>A string, number, or function</span><span class="when-choice">typeof</span></div>
<div class="when-row"><span>Anything that might be null</span><span class="when-choice">=== null before the property</span></div>
<div class="when-row"><span>A plain object, not a list</span><span class="when-choice">reject arrays</span></div>
<div class="when-row"><span>null and undefined together</span><span class="when-choice">== null, knowing it is coercion</span></div>
</div>
</section>
