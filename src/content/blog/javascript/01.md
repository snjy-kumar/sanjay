What it is
</h2>
<p>I fixed a small bug in a personal project by deleting one <code>var</code>. A loop leaked its counter past the block, and another function reused the name. The output looked random because the binding was not local to the block I was reading.</p>
<p><code>var</code> is function-scoped, or global if you are not inside a function. It ignores <code>{}</code> blocks, can be redeclared, and is hoisted as <code>undefined</code>. <code>let</code> and <code>const</code> are block-scoped. <code>const</code> forbids rebinding the name. It does not freeze an object. <code>user.name = &quot;Ada&quot;</code> is still allowed when <code>user</code> is <code>const</code>.</p>
<p>A <code>for (var i = 0; i &lt; 3; i++)</code> loop leaves <code>i === 3</code> after the loop, and every closure created in the loop sees that same <code>i</code>. <code>for (let i ...)</code> gives each iteration its own binding. That is the bug I hit, not a style preference.</p>
<p>New code uses <code>const</code> for names that are not reassigned and <code>let</code> when they are. I leave <code>var</code> alone in old files unless I am already editing that function and can see every use of the name.</p>

Old
</h2>
<p><strong>Wrong approach: var for every binding, including loop counters</strong></p>
<p><strong>Best case.</strong> A single <code>var</code> at the top of a short function, never closed over, never reused. It behaves, and it is still harder to read than <code>const</code>.</p>
<p><strong>Worst case.</strong> Two loops share <code>i</code>, or a click handler created inside the loop runs later and sees the final index for every button.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M7 2.15 11.7 7 7 11.85 2.3 7z"/></svg>
New
</h2>
<p><strong>Right approach: const by default, let when the name is reassigned, block scope for loop indexes</strong></p>
<p><strong>Best case.</strong> The loop variable dies with the loop. A closed-over <code>let</code> index is the index from that iteration. <code>const</code> makes accidental reassignment a thrown error at the assignment, not a quiet second meaning.</p>
<p><strong>Worst case.</strong> <code>const</code> on a value I immediately need to rebind, which pushes me into awkward rewrites. That case is <code>let</code>. <code>const</code> is the default, not a law against change.</p>
<p>After: <code>i</code> stays in the loop, and <code>label</code> is a binding I do not reassign.</p>

<section class="section" id="when">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use <code>const</code> for a name you will not rebind. Use <code>let</code> for a counter, an accumulator, or any deliberate reassignment. Do not use <code>var</code> in new code. Remember that <code>const</code> protects the binding, not the contents of an object or array.</p>
<div class="when">
<div class="when-row"><span>The name is never reassigned</span><span class="when-choice">const</span></div>
<div class="when-row"><span>The name is reassigned on purpose</span><span class="when-choice">let</span></div>
<div class="when-row"><span>A loop index closed over by a callback</span><span class="when-choice">let</span></div>
<div class="when-row"><span>Legacy var in a file you are not editing</span><span class="when-choice">leave it</span></div>
</div>
</section>
