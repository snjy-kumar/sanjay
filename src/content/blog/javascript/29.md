What it is
</h2>
<p>A filter for <code>React &amp; DOM</code> became two query parameters because I concatenated the URL. The ampersand started a new pair. Spaces and question marks have rules too. Hand-built query strings fail the first time a real title shows up.</p>
<p><code>URLSearchParams</code> encodes values, keeps repeated keys, and has <code>get</code>, <code>set</code>, <code>append</code>, and <code>delete</code>. <code>new URLSearchParams({ q: query, page: &quot;1&quot; })</code> produces a string I can put after <code>?</code>. <code>String(params)</code> or `<code> params.toString() </code><code> is the encoded form, where a space is </code>+<code> and </code>&amp;` inside a value is percent-encoded.</p>
<p>For the address bar I use <code>URL</code>, not string surgery. <code>const next = new URL(location.href)</code> gives me <code>next.searchParams</code>. <code>set</code> replaces <code>q</code>. <code>history.pushState</code> updates the visible URL without a navigation. The page can be refreshed and shared, and the filter is still in the query.</p>
<p>The address bar is data. I use the URL API so the grammar of the query is not something I reimplement inside a template string.</p>
</section>

Old
</h2>
<p><strong>Wrong approach: concatenate query values into a string</strong></p>
<p><strong>Best case.</strong> The value is a token you minted, with no reserved characters, and you encoded it yourself once. The next value will not be so polite.</p>
<p><strong>Worst case.</strong> <code>&amp;</code>, <code>=</code>, <code>?</code>, spaces, and non-ASCII titles change the shape of the query. A shared link does not round-trip the filter.</p>

New
</h2>
<p><strong>Right approach: URLSearchParams for the body of the query, URL to edit the current location</strong></p>
<p><strong>Best case.</strong> <code>searchUrl(&quot;React &amp; DOM&quot;)</code> keeps one <code>q</code> value. <code>replaceQuery</code> updates <code>q</code> without dropping unrelated params already on the page.</p>
<p><strong>Worst case.</strong> Building a <code>URL</code> with a relative path and no base, which throws. I pass <code>location.href</code> or an absolute base. Params themselves do not need a base.</p>
<p>After: encoding is the params object’s job, and the live URL is edited through <code>searchParams</code>.</p>

When to use which
</h2>
<p>Use <code>URLSearchParams</code> whenever you build or read a query. Use <code>URL</code> when you are changing the current address. Use <code>get</code> and <code>set</code> rather than splitting on <code>&amp;</code>. Encode with the API, not with a hand-rolled replace.</p>
<div class="when">
<div class="when-row"><span>Build a query string</span><span class="when-choice">URLSearchParams</span></div>
<div class="when-row"><span>Update the address bar</span><span class="when-choice">new URL(location.href)</span></div>
<div class="when-row"><span>Read one parameter</span><span class="when-choice">searchParams.get</span></div>
<div class="when-row"><span>A value that may contain &amp; or spaces</span><span class="when-choice">let the params object encode it</span></div>
</div>
