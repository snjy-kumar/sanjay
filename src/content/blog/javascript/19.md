<h2>

What it is
</h2>
<p>I wrote <code>profile?.company?.name</code> everywhere and turned a required missing field into a blank card. Optional chaining returns <code>undefined</code> when the base is <code>null</code> or <code>undefined</code>, and then <code>??</code> can substitute a string. The expression is short. It also deletes the difference between “no company on purpose” and “the payload is broken.”</p>
<p>I use <code>?.</code> at a boundary that is genuinely optional: a plugin that might be missing, a field the product allows to be absent, a DOM query that might not find a node. I do not use it to silence a contract. If the screen cannot render a person without a company name, the missing name should take a visible path, not become <code>&quot;&quot;</code>.</p>
<p>After I have checked, I read <code>profile.company.name</code> without another <code>?.</code>. The check is the documentation. A chain of question marks on every access hides which link was empty, so the bug loses its context.</p>
<p>A shorter expression is not always a safer one. Required data should fail in a way I can see and fix.</p>
</section>

Old
</h2>
<p><strong>Wrong approach: chain ?. and ?? until the type errors and the blanks go away</strong></p>
<p><strong>Best case.</strong> The field really is optional and an empty label is the designed UI for absence.</p>
<p><strong>Worst case.</strong> A required field disappears. I ship a blank card, and the broken payload is indistinguishable from a person who has no company.</p>
<p>Before: every access is optional, and the fallback is an empty string.</p>

New
</h2>
<p><strong>Right approach: use ?. to read an uncertain path, then branch when the value is required</strong></p>
<p><strong>Best case.</strong> Optional data stays a one-line read. Required data produces <code>{ ok: false, label: &quot;Company missing&quot; }</code>, which the screen can show.</p>
<p><strong>Worst case.</strong> Throwing a raw exception for every optional field and taking down a page that had a reasonable fallback. I reserve the loud path for data the screen cannot honestly hide.</p>
<p>After: the missing company is a result, not an empty string pretending to be a name.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use <code>?.</code> when absence is expected and the caller handles <code>undefined</code>. After a check, access the property normally. Do not combine <code>?.</code> with <code>?? &quot;&quot;</code> on a required field. If several required fields can be missing, return a message that names the one you checked.</p>
<div class="when">
<div class="when-row"><span>A plugin, query, or optional field</span><span class="when-choice">?.</span></div>
<div class="when-row"><span>A required field that is missing</span><span class="when-choice">a visible branch</span></div>
<div class="when-row"><span>You already proved the object exists</span><span class="when-choice">plain access</span></div>
<div class="when-row"><span>You need the failing property’s name</span><span class="when-choice">check one link at a time</span></div>
</div>
</section>
