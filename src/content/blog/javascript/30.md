What it is
</h2>
<p>I cleaned up a personal demo by letting a button announce “save requested” instead of reaching into a sibling and writing “Saved” straight into its markup. The button knew the parent’s structure. The parent had no say in the failure path. The snippet looked interactive and could not tell the truth.</p>
<p><code>CustomEvent</code> is a small browser boundary. The button dispatches <code>profile:save</code> with a detail object that holds the id and nothing else. The form listens, because the form owns the request. <code>bubbles: true</code> lets the event travel to that listener. Detail is plain data, not a function and not a DOM node.</p>
<p>The handler shows “Saving…”, awaits the save, then shows “Saved” or “Could not save”. The button does not know which element displays the status. That ignorance is the point. A portfolio snippet that only sets “Saved” is a demo of the happy path. The honest version has a loading line and a failure line because real clicks fail.</p>
<p>An event is not an application framework. It is a contract for independent DOM pieces on one page. I keep the detail small, I remove the listener when the form goes away, and I do not pretend the network always works.</p>
</section>

New
</h2>
<p><strong>Right approach: dispatch a small event and let the owner handle loading and failure</strong></p>
<p><strong>Best case.</strong> The button carries an id. The form shows Saving, Saved, or Could not save. Moving the status markup does not require editing the button.</p>
<p><strong>Worst case.</strong> A detail object that includes DOM nodes or callbacks, so the event becomes a backdoor. I keep detail to strings and numbers, and I unsubscribe when the form is removed.</p>
<p>After: success is one branch of the promise, not a string the button writes immediately.</p>

When to use which
</h2>
<p>Use a <code>CustomEvent</code> when two DOM pieces on the same page need a small contract and should not query each other’s internals. Put the work in the listener that owns the outcome. Show loading and failure. Do not use an event to hide a missing function call in the same module. If they share a scope, call the function.</p>
<div class="when">
<div class="when-row"><span>Two independent pieces of one page</span><span class="when-choice">CustomEvent with a small detail</span></div>
<div class="when-row"><span>Caller and callee in one module</span><span class="when-choice">a function call</span></div>
<div class="when-row"><span>The save can fail</span><span class="when-choice">show the failure</span></div>
<div class="when-row"><span>The listener’s node is removed</span><span class="when-choice">removeEventListener</span></div>
</div>
