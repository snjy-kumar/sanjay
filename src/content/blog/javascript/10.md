What it is
</h2>
<p>One malformed value in <code>localStorage</code> crashed a personal page before the empty state could render. <code>JSON.parse</code> throws a <code>SyntaxError</code> on text that is not JSON. The UI had no <code>catch</code>, so the exception escaped the render path.</p>
<p>Valid JSON is not a valid settings object. <code>&quot;null&quot;</code>, <code>&quot;[]&quot;</code>, and <code>&quot;{\&quot;theme\&quot;:1}&quot;</code> all parse. The syntax succeeded and the shape was still wrong. A parser that only wraps <code>JSON.parse</code> in <code>try</code> will accept an array and then throw later on <code>settings.theme</code>.</p>
<p>I parse at the boundary and handle both failures. No text means the default. A throw means the default. A parsed value that is not an object, or whose <code>theme</code> is not one of the themes I know, means the default. I return a fresh object either way, so a weird parsed value cannot leak into the rest of the page.</p>
<p>I treat JSON as untrusted even when I wrote it. An older version of my own app is still a different writer.</p>
</section>

New

<p><strong>Right approach: catch the syntax error, then check the shape you actually depend on</strong></p>
<p><strong>Best case.</strong> Missing text, broken text, <code>null</code>, arrays, and unknown themes all return <code>{ theme: &quot;light&quot; }</code>. The caller can render without another guard.</p>
<p><strong>Worst case.</strong> A fallback so quiet that I never notice my storage key is corrupt. I keep the default, and if I care about the corruption I log it beside the <code>catch</code> without letting it escape.</p>
<p>After: the only returned themes are the two strings the UI knows.</p>

When to use which
</h2>
<p>Wrap <code>JSON.parse</code> in <code>try/catch</code> whenever the string came from storage, a file, or a response body you are not certain about. Check the shape afterward. Prefer <code>response.json()</code> for fetch, and still validate the result. Do not use <code>JSON.parse</code> on data you already have as an object.</p>
<div class="when">
<div class="when-row"><span>Text from storage or a file</span><span class="when-choice">try/catch plus a shape check</span></div>
<div class="when-row"><span>A fetch response</span><span class="when-choice">response.json(), then validate</span></div>
<div class="when-row"><span>A value you just stringified</span><span class="when-choice">parse only if it crossed a boundary</span></div>
<div class="when-row"><span>You need a Date or undefined</span><span class="when-choice">JSON will not preserve them</span></div>
</div>
