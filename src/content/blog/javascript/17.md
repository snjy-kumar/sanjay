What it is
</h2>
<p>I moved a file into a module and a top-level <code>const</code> disappeared from <code>window</code>. I had been using an accidental global as the API between two scripts. Classic scripts share that global scope. Modules do not. Each module has its own scope, and the only names that leave it are the ones I <code>export</code>.</p>
<p>Modules are strict mode. They are deferred by default: the browser downloads them, builds the graph, and runs them after the document is parsed, in dependency order, before <code>DOMContentLoaded</code>. A classic script without <code>defer</code> or <code>type=&quot;module&quot;</code> can block parsing and runs in document order as it is reached. Adding <code>type=&quot;module&quot;</code> changes timing as well as scope.</p>
<p><code>import</code> and <code>export</code> are the boundary. A name collision between files stops being a silent overwrite. The HTML points at the entry module, and that module imports what it needs. I stopped hanging <code>window.api = api</code> as a way to share a function.</p>
<p>Modules are not “scripts with a nicer filename.” They are a dependency graph with a private top level. If I need a value on <code>window</code> for a reason I can explain, I assign it on purpose. I do not get it for free.</p>
</section>

<p><strong>Worst case.</strong> A second file assigns the same name, or a script runs before the global exists. The failure is a timing bug that looks like a missing function.</p>

New
</h2>
<p><strong>Right approach: export the function and import it where it is used</strong></p>
<p><strong>Best case.</strong> The dependency is a line I can search. The name is scoped. Module order follows the imports, not the order of script tags I forgot to update.</p>
<p><strong>Worst case.</strong> A module imported for its side effect only, with no exports, so loading it still mutates the page invisibly. I export a function and call it from the entry file instead.</p>
<p>After: <code>loadProfile</code> crosses the file boundary because it was exported.</p>

When to use which
</h2>
<p>Use <code>type=&quot;module&quot;</code> for new browser code and pass values with <code>import</code> and <code>export</code>. Use a classic script only for a file that must stay global or that you cannot convert yet. Remember that modules are deferred and strict. Do not rely on <code>window</code> to stitch files together.</p>
<div class="when">
<div class="when-row"><span>New browser code</span><span class="when-choice">type=module and import</span></div>
<div class="when-row"><span>A name another file needs</span><span class="when-choice">export it</span></div>
<div class="when-row"><span>A legacy file that sets globals</span><span class="when-choice">classic script, isolated</span></div>
<div class="when-row"><span>Code that must run mid-parse</span><span class="when-choice">you probably still wanted defer or a module</span></div>
</div>
</section>
