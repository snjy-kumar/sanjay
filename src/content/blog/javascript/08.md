What it is
</h2>
<p>I used <code>map</code> to save each item, then wondered why the returned array was full of <code>undefined</code>. <code>map</code> always returns a new array, one slot per element, filled with whatever the callback returns. A callback that only calls <code>saveCard</code> returns <code>undefined</code>. I had asked for a transformed array and then ignored it.</p>
<p><code>forEach</code> visits items and returns <code>undefined</code>. <code>filter</code> returns the elements whose callback returns true. <code>find</code> returns the first match or <code>undefined</code>. <code>some</code> and <code>every</code> return booleans. <code>reduce</code> builds one accumulated result. The method name is the contract. I pick the one whose return value I will actually use.</p>
<p>I also stop mutating the source array inside <code>map</code> or <code>filter</code>. Those callbacks should be pure. A save, a DOM write, or a <code>push</code> onto some other array is a side effect and belongs in <code>forEach</code> or a plain loop, where nobody expects a new list.</p>
<p>Chaining is fine when each step’s result is the next step’s input: filter, then map. Chaining <code>map</code> onto a <code>forEach</code> is not, because <code>forEach</code> returns <code>undefined</code>.</p>

New
</h2>
<p><strong>Right approach: pick the method whose return value matches the next line</strong></p>
<p><strong>Best case.</strong> <code>forEach</code> makes the saves. <code>filter</code> produces the visible list. Neither result surprises the following line.</p>
<p><strong>Worst case.</strong> A <code>reduce</code> that both filters and saves and sorts because I wanted one pass. It is faster only if I measured it, and it is harder to read immediately. I split until a profile says otherwise.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use <code>map</code> when you need a new array of the same length. Use <code>filter</code> to drop elements. Use <code>find</code> for one element. Use <code>forEach</code> or a <code>for...of</code> loop for side effects. Use <code>reduce</code> when you are building a single non-array result and the simpler methods do not say it.</p>
<div class="when">
<div class="when-row"><span>A new value per element</span><span class="when-choice">map</span></div>
<div class="when-row"><span>A subset of the elements</span><span class="when-choice">filter</span></div>
<div class="when-row"><span>The first match</span><span class="when-choice">find</span></div>
<div class="when-row"><span>Save, log, or write the DOM</span><span class="when-choice">forEach or for...of</span></div>
</div>
</section>
