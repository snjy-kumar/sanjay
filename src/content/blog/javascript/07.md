What it is
</h2>
<p>I thought a delayed button handler had lost its setting. It had captured the setting from the scope that created it. The callback was remembering on purpose. I was the one who expected it to see a later assignment through a different binding.</p>
<p>A closure is a function plus the lexical environment it was created in. <code>makeCounter</code> returns a function that can still see <code>n</code> after <code>makeCounter</code> has returned. Each call to <code>makeCounter</code> creates a new <code>n</code>. Two counters do not share a number.</p>
<p>That privacy is the useful case: a small piece of state without a global. The sharp edge is lifetime. A listener, a timer, or a promise callback keeps that environment alive. If it closed over a large object or an old <code>query</code>, it will keep using that object until the callback itself is released.</p>
<p>When a callback “sees the past,” I look at which binding it closed over and when that function was created. I do not blame the timer first. The timer only calls the function. The function already has its scope.</p>

New
</h2>
<p><strong>Right approach: decide which scope the callback should keep, and create the function in that scope</strong></p>
<p><strong>Best case.</strong> Each counter has its own <code>n</code>. The button handler has the <code>label</code> I passed in. I can test <code>next()</code> without a page.</p>
<p><strong>Worst case.</strong> A closure that retains a huge structure for the life of a listener I never remove. The capture is correct and the lifetime is too long. I remove the listener.</p>
<p>After: the counter’s state is the closed-over <code>n</code>, and each factory call gets a new one.</p>

<section class="section" id="when">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use a closure for private state and for callbacks that should remember a particular value. If the callback must see a newer value, close over a binding you update, or pass the new value into a new function. Remove long-lived listeners so the captured scope can be collected.</p>
<div class="when">
<div class="when-row"><span>Private state for one feature</span><span class="when-choice">a factory function</span></div>
<div class="when-row"><span>A callback that should remember one value</span><span class="when-choice">close over that binding</span></div>
<div class="when-row"><span>A callback that must see later updates</span><span class="when-choice">update the binding, or recreate the function</span></div>
<div class="when-row"><span>A listener that outlived the screen</span><span class="when-choice">remove it</span></div>
</div>
</section>
