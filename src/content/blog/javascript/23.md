<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><circle cx="7" cy="7" r="4.75"/><path d="M7 6.35v3.45"/><path d="M7 4.4v.02" stroke-width="1.8"/></svg>
What it is
</h2>
<p>A nested link inside a card navigated even after I tried to “stop the click.” I had called <code>stopPropagation</code>. The card’s listener went quiet. The browser still followed the link, because the default action was never canceled. The two methods solve different problems, and I had picked the one that matched a different bug.</p>
<p><code>preventDefault()</code> cancels the browser’s built-in action when the event is cancelable: following a link, submitting a form, checking a box on some paths. It does not stop the event from reaching other listeners. <code>stopPropagation()</code> stops the event traveling to ancestor listeners. It does not cancel the default action. <code>stopImmediatePropagation()</code> also blocks other listeners on the same element. I almost never need that one.</p>
<p>I name the behavior I am canceling. If the bug is navigation, I prevent the default and then do the in-page work. If the bug is a parent handler also opening the card, I stop propagation, and I still prevent the default if the control is a link or a submit button.</p>
<p>I do not call both “to be safe” on every click. A parent that never hears the event becomes a second bug: analytics, a dialog backdrop, or a delegated handler goes silent.</p>
</section>

New
</h2>
<p><strong>Right approach: preventDefault to cancel navigation or submit, stopPropagation only to cut off ancestors</strong></p>
<p><strong>Best case.</strong> The link stays on the page and <code>openInPage</code> runs. Other listeners still see the event unless I have a reason to hide it.</p>
<p><strong>Worst case.</strong> Preventing the default on a control whose browser behavior I still wanted, such as a checkbox or a real external link. I prevent only the action I am replacing.</p>
<p>After: the handler names the navigation it is replacing.</p>

<section class="section" id="when">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>If the browser is about to navigate, submit, or otherwise act, call <code>preventDefault</code>. If an ancestor listener must not run, call <code>stopPropagation</code>. If both are true, call both, and know why each is there. Do not use either as a generic mute button.</p>
<div class="when">
<div class="when-row"><span>Replace a link or submit action</span><span class="when-choice">preventDefault</span></div>
<div class="when-row"><span>Keep a parent handler from also running</span><span class="when-choice">stopPropagation</span></div>
<div class="when-row"><span>Both the default and the parent are wrong</span><span class="when-choice">both, for those two reasons</span></div>
<div class="when-row"><span>You want other listeners on the same node to run</span><span class="when-choice">do not stopImmediatePropagation</span></div>
</div>
</section>
