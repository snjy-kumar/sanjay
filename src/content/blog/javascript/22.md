<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><circle cx="7" cy="7" r="4.75"/><path d="M7 6.35v3.45"/><path d="M7 4.4v.02" stroke-width="1.8"/></svg>
What it is
</h2>
<p>A dynamic list stopped responding because new rows never received the handler I attached during the first render. I had queried the buttons once and listened to each. Buttons created later were silent. Re-querying after every update was easy to forget and easy to double-bind.</p>
<p>Events bubble. A click on a button inside a list also reaches the list, unless something stops it. I listen once on the list, which stays in the document. The handler asks <code>event.target.closest(&quot;[data-remove]&quot;)</code> for the control that was actually clicked, including when the click landed on an icon inside the button.</p>
<p><code>closest</code> can walk out of the list if I am not careful, so I also check <code>list.contains(button)</code>. Then the handler only acts on controls inside the element I subscribed to. New rows work without a new listener. Removed rows do not leave a listener behind.</p>
<p>Delegation is one lifecycle for a changing collection. The point is not fewer lines. The point is that the listener and the parent share a lifetime.</p>
</section>

Old

New
</h2>
<p><strong>Right approach: listen on the stable parent and resolve the target with closest</strong></p>
<p><strong>Best case.</strong> Rows can be added and removed. One listener stays. A click on an icon inside the button still resolves to the button that carries <code>data-remove</code>.</p>
<p><strong>Worst case.</strong> A selector so broad that a nested list’s button is handled by the outer list too. <code>contains</code> limits the match to the parent I bound.</p>
<p>After: the handler ignores clicks that are not on a remove control inside this list.</p>

<section class="section" id="when">
<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Delegate when children come and go and the parent is stable. Bind the child directly when there is one long-lived control. Use <code>closest</code> so inner icons work, and check containment so the selector cannot escape the parent. Stop the listener when the parent itself goes away.</p>
<div class="when">
<div class="when-row"><span>Rows are added and removed</span><span class="when-choice">one listener on the parent</span></div>
<div class="when-row"><span>A single button that stays</span><span class="when-choice">listen on that button</span></div>
<div class="when-row"><span>The click target is an icon inside the control</span><span class="when-choice">closest</span></div>
<div class="when-row"><span>Nested lists with the same selector</span><span class="when-choice">contains</span></div>
</div>
</section>
