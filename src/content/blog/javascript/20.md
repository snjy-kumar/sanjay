What it is
</h2>
<p>A draft copy in a personal project lost an <code>undefined</code> field and turned a <code>Date</code> into a string. I had cloned with <code>JSON.parse(JSON.stringify(draft))</code>. JSON has a smaller type set than JavaScript. <code>undefined</code> object fields are omitted, <code>Date</code> becomes an ISO string, <code>NaN</code> and <code>Infinity</code> become <code>null</code>, and a cycle throws. The copy type-checked in my head and not in the running page.</p>
<p><code>structuredClone</code> uses the platform’s structured-clone algorithm. Dates, <code>Map</code>, <code>Set</code>, and nested plain data survive, and cycles are allowed. Functions, DOM nodes, and some class instances still cannot be cloned. A throw from <code>structuredClone</code> means I tried to copy something it does not support. I catch that at the boundary rather than switching back to JSON quietly.</p>
<p>Often I do not need a deep copy. A title change is <code>const next = { ...draft, title: &quot;Updated&quot; }</code>. The spread is shallow, which is what I want when I am replacing one field and the nested objects are not mutated later. If I will mutate a nested object, a shallow copy is not enough and I clone or rebuild that level.</p>
<p>Cloning is a data-model decision. I pick the tool that preserves the values I will read, and I prefer a targeted copy when I know the field.</p>

New
</h2>
<p><strong>Right approach: structuredClone for supported data, or a shallow copy of the field you change</strong></p>
<p><strong>Best case.</strong> A <code>Date</code> on the copy is still a <code>Date</code>. A title change does not clone the whole tree. Cycles of plain data clone instead of throwing.</p>
<p><strong>Worst case.</strong> <code>structuredClone</code> on a value that holds a function or a DOM node. It throws. I map the fields I can store, and I leave the live node where it is.</p>
<p>After: the copy path matches the data. The title update does not pretend to be a deep clone.</p>

When to use which
</h2>
<p>Use <code>structuredClone</code> for a real deep copy of supported data. Use a spread or <code>Object.assign</code> for a shallow one-field update. Use JSON only when you are actually serializing. Do not JSON-clone to “be safe.”</p>
<div class="when">
<div class="when-row"><span>A deep copy of data the platform supports</span><span class="when-choice">structuredClone</span></div>
<div class="when-row"><span>Replace one field, no nested writes</span><span class="when-choice">object spread</span></div>
<div class="when-row"><span>You are saving text</span><span class="when-choice">JSON.stringify, knowing the limits</span></div>
<div class="when-row"><span>The value holds a function or a node</span><span class="when-choice">map the data fields instead</span></div>
</div>
