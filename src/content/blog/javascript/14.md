What it is
</h2>
<p>A dashboard in a personal project hid every widget because one optional request rejected. <code>Promise.all</code> is fail-fast: the returned promise rejects with the first rejection, and I do not get the values that already succeeded through that rejection path. For a screen where every panel is required, that is the right product behavior. For independent cards, it is not.</p>
<p><code>Promise.allSettled</code> waits for every promise and returns <code>{ status: &quot;fulfilled&quot;, value }</code> or <code>{ status: &quot;rejected&quot;, reason }</code>. It does not reject because of a member. I render each result on its own.</p>
<p>I still use <code>Promise.all</code> when a partial result would be a lie: saving a record that needs both the profile write and the index write, for example. Showing half a commit as success would be worse than failing the whole action.</p>
<p>The helper encodes the product rule. I pick it from whether partial success is honest, not from which name is newer.</p>
</section>

New
</h2>
<p><strong>Right approach: allSettled when each result can stand alone, all when every result is required</strong></p>
<p><strong>Best case.</strong> The profile renders. The activity slot shows its own error. Neither outcome is implied by the other.</p>
<p><strong>Worst case.</strong> <code>allSettled</code> on a transaction that must be atomic. I would display a half-saved state as if it were a normal partial UI. That case stays on <code>Promise.all</code>.</p>

<h2>
<svg class="ico" width="14" height="14" viewBox="0 0 14 14" aria-hidden="true" fill="none" stroke="#111" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round"><path d="M3.6 2.4v9.2"/><path d="M3.6 6.4h4.35"/><path d="M7.95 6.4 11.15 3.5"/><path d="M7.95 6.4 11.15 9.3"/></svg>
When to use which
</h2>
<p>Use <code>Promise.all</code> when failure of one means failure of the group, and you want the rejection. Use <code>Promise.allSettled</code> when you will render or log every member. Do not mix them to “be safe.” The choice is the product rule.</p>
<div class="when">
<div class="when-row"><span>Every result is required</span><span class="when-choice">Promise.all</span></div>
<div class="when-row"><span>Each panel can fail alone</span><span class="when-choice">Promise.allSettled</span></div>
<div class="when-row"><span>You need the first success</span><span class="when-choice">Promise.any</span></div>
<div class="when-row"><span>You only need the first settlement</span><span class="when-choice">Promise.race</span></div>
</div>
</section>
