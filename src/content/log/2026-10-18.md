The lifting state note. The pattern I keep hitting: two components look
like they need shared state, so I lift it, and then the parent grows a
`useEffect` to keep the two in sync, and now there are two sources of truth.

Found the same shape in my own code three times this week. Not the same
bug, the same mistake.

The fix is not "do not lift state". It is "lift it when two components
genuinely own the same value, not when they need the same value".
