## 2.1 Sets

### In one sentence

A set is an unordered collection of distinct objects, and everything about it is decided by which
objects are in it and which are not.

### The idea

#### What a set is

A **set** is an unordered collection of objects called its **elements** or **members**. We write a ∈ A
for "a is an element of A" and a ∉ A for "a is not". Order does not matter and repeats do not count:
the set of letters in "banana" is the set containing b, a and n.

That "only membership matters" rule is the whole definition. Two descriptions that pick out the same
members describe the same set, however different they look.

#### Two ways to describe a set

The **roster method** lists the elements between braces: the set of vowels is a, e, i, o, u in braces.
An ellipsis can stand for a clear pattern, as in 1, 2, 3, and so on up to 99.

**Set builder notation** gives a rule instead: "the set of all x such that x is an odd positive integer
less than 10". It is a predicate from chapter 1 turned into a collection, and it is how infinite sets
are described.

Standard sets have names. **N** is the natural numbers 0, 1, 2 and on (the book includes 0). **Z** is
the integers, **Z⁺** the positive integers, **Q** the rationals, **R** the reals, **R⁺** the positive
reals and **C** the complex numbers. **Intervals** such as [a, b] (both ends included) and (a, b)
(both excluded) are sets of reals.

#### Equality, subsets and the empty set

Sets A and B are **equal** when they have the same elements: ∀x (x ∈ A ↔ x ∈ B). A is a **subset** of B,
A ⊆ B, when every element of A is in B: ∀x (x ∈ A → x ∈ B). A is a **proper subset**, A ⊂ B, when A ⊆ B
and A is not B.

The **empty set** ∅ has no elements. It is a subset of every set, because "every element of ∅ is in B"
is vacuously true. A set with one element is a **singleton**. Note that the set containing ∅ is not
empty; it has one element, and that element happens to be a set.

To prove A equals B, the standard move is to prove A ⊆ B and B ⊆ A. That is the biconditional from
chapter 1 split into its two directions.

#### Size

A set is **finite** if it has exactly n distinct elements for some natural number n. Then n is its
**cardinality**, written |A|. |∅| is 0. A set that is not finite is **infinite**; section 2.5 is about
measuring those.

#### Power sets

The **power set** P(A) is the set of all subsets of A, including ∅ and A itself. If A has n elements,
P(A) has 2 to the n, because each element is either in a subset or not: two choices, n times.

#### Tuples and Cartesian products

An **ordered n-tuple** (a1, a2, ..., an) is a list where order matters. Two tuples are equal when they
agree in every position. An ordered pair is a 2-tuple, and (1, 2) is not (2, 1).

The **Cartesian product** A × B is the set of all ordered pairs (a, b) with a ∈ A and b ∈ B. It has |A|
times |B| elements. A subset of A × B is a **relation** from A to B, the subject of chapter 9.

#### Quantifiers with domains, and truth sets

∀x ∈ S P(x) is shorthand for ∀x (x ∈ S → P(x)), and ∃x ∈ S P(x) for ∃x (x ∈ S ∧ P(x)). This is the
restricted-domain pattern of 1.4 in compact form.

The **truth set** of a predicate P over domain D is the set of x in D for which P(x) is true. It is
exactly how set builder notation and chapter 1 connect.

#### Naive set theory and the paradox

Allowing any rule to define a set leads to trouble. **Russell's paradox**: let S be the set of all sets
that are not members of themselves. Is S a member of S? If it is, it should not be; if it is not, it
should be.

Axiomatic set theory avoids this by restricting which rules make sets. For this book, and for programming,
the naive picture is fine as long as sets are built from things already known to exist.

### Worked example

**Simple: power set and product in code.**

```ts
function powerSet<T>(xs: T[]): T[][] {
  return xs.reduce<T[][]>((acc, x) => acc.concat(acc.map(s => [...s, x])), [[]]);
}
const cart = <T, U>(a: T[], b: U[]) => a.flatMap(x => b.map(y => [x, y] as [T, U]));
console.log('P({a,b,c}):', JSON.stringify(powerSet(['a', 'b', 'c'])), 'size', powerSet(['a', 'b', 'c']).length);
console.log('A x B:', JSON.stringify(cart([1, 2], ['x', 'y', 'z'])));
```

```text
P({a,b,c}): [[],["a"],["b"],["a","b"],["c"],["a","c"],["b","c"],["a","b","c"]] size 8
A x B: [[1,"x"],[1,"y"],[1,"z"],[2,"x"],[2,"y"],[2,"z"]]
```

`powerSet` builds the answer the way the 2 to the n argument counts it. Each new element doubles the
list: every old subset, plus every old subset with the new element added. 2 by 3 gives 6 pairs.

**Realistic: what "equal" means in JavaScript.** A `Set` of arrays compares arrays by identity, not by
membership.

```ts
const s1 = new Set([[1, 2]]);
console.log('Set of arrays has [1,2]?', s1.has([1, 2]));
const s2 = new Set(['1,2']);
console.log('Set of keys has "1,2"?', s2.has([1, 2].join(',')));
```

```text
Set of arrays has [1,2]? false
Set of keys has "1,2"? true
```

The mathematical set of pairs would contain (1, 2). The JavaScript set holds one particular array object,
and a new array with the same contents is a different object. The fix is to store a canonical key, here
the joined string.

### Common mistake

**Confusing ∈ and ⊆.** The wrong way: writing 1 ⊆ the set containing 1, 2. The number 1 is an
element, not a set of elements, so the right statement is 1 ∈ the set. The subset statement is "the set
containing 1" ⊆ "the set containing 1, 2".

A related trap: ∅ and the set containing ∅ are different. The first has size 0, the second size 1. In
code, `[]` and `[[]]` differ in exactly this way, and `[[]].length` is 1.

### In real systems

`Set` in TypeScript, `HashSet` in Java and `set` in Python are finite sets. Database tables under SQL's
`DISTINCT` are sets of tuples; without `DISTINCT`, they are bags, where repeats count, which is why
`COUNT(*)` and `COUNT(DISTINCT id)` can disagree.

Cartesian products appear as SQL cross joins, as the combinations in a test matrix (every browser times
every OS), and as the reason a missing join condition explodes the row count. Power sets are the space of
feature-flag combinations: 20 flags give over a million configurations.

## 2.2 Set operations

### In one sentence

Union, intersection, difference and complement combine sets the way or, and, and-not and not combine
propositions, so every set identity is a logical equivalence in disguise.

### The idea

#### The four operations

The **union** A ∪ B is the set of elements in A or B (or both). The **intersection** A ∩ B is the set
of elements in both. Two sets are **disjoint** when their intersection is empty.

The **difference** A − B is the set of elements in A but not in B. Some books call it the relative
complement of B in A. The **complement** of A, written with a bar over A, is U − A, where U is a
**universal set** containing everything under discussion.

The complement only makes sense once U is fixed. The complement of the even numbers is the odd numbers if
U is Z, and something much bigger if U is R.

#### Venn diagrams

A **Venn diagram** draws U as a rectangle and each set as a circle inside it. Shading shows a set built
from them. Venn diagrams are good for intuition and for checking an identity on two or three sets; they
are not proofs on their own.

#### Inclusion-exclusion for two sets

|A ∪ B| equals |A| plus |B| minus |A ∩ B|. Adding |A| and |B| counts the overlap twice, so it is
subtracted once. Chapter 8 generalises this to any number of sets.

#### Set identities

Every law of 1.3 has a set version, with ∪ for or, ∩ for and, complement for not, ∅ for F and U for T.
The ones used most:

| Name | Identity |
|---|---|
| Identity | A ∩ U is A; A ∪ ∅ is A |
| Domination | A ∪ U is U; A ∩ ∅ is ∅ |
| Complementation | the complement of the complement of A is A |
| Commutative, associative | as for or and and |
| Distributive | A ∪ (B ∩ C) is (A ∪ B) ∩ (A ∪ C); A ∩ (B ∪ C) is (A ∩ B) ∪ (A ∩ C) |
| De Morgan | complement of A ∪ B is (complement A) ∩ (complement B); complement of A ∩ B is (complement A) ∪ (complement B) |
| Absorption | A ∪ (A ∩ B) is A; A ∩ (A ∪ B) is A |
| Complement | A ∪ complement A is U; A ∩ complement A is ∅ |

#### Three ways to prove an identity

1. **Membership (double inclusion).** Show every element of the left side is in the right, and back.
2. **Membership table.** Like a truth table: one row for each combination of "in A or not, in B or not",
   with a 1 or 0 for each side. Equal columns prove the identity.
3. **Laws.** Rewrite one side into the other, one named identity per line.

#### Generalised unions and intersections

The union of A1 to An is the set of elements in at least one Ai; the intersection is the set of elements
in all of them. They are the set versions of ∃i and ∀i. For an empty family, the union is ∅ and the
intersection is U, matching the empty-domain rule for quantifiers.

#### Sets as bit strings

If U has n elements in a fixed order, a subset is an n-bit string: bit i is 1 when element i is in the
subset. Then union is bitwise OR, intersection is AND, and complement is NOT. This is how many fast set
implementations work.

### Worked example

**Simple: the operations in code, and inclusion-exclusion.**

```ts
const A = new Set([1, 2, 3, 4]); const B = new Set([3, 4, 5]);
const union = <T,>(a: Set<T>, b: Set<T>) => new Set([...a, ...b]);
const inter = <T,>(a: Set<T>, b: Set<T>) => new Set([...a].filter(x => b.has(x)));
const diff = <T,>(a: Set<T>, b: Set<T>) => new Set([...a].filter(x => !b.has(x)));
const sym = <T,>(a: Set<T>, b: Set<T>) => union(diff(a, b), diff(b, a));
console.log('union', [...union(A, B)], 'inter', [...inter(A, B)], 'A-B', [...diff(A, B)], 'sym', [...sym(A, B)]);
console.log('|A u B| =', union(A, B).size, '= |A| + |B| - |A n B| =', A.size + B.size - inter(A, B).size);
```

```text
union [ 1, 2, 3, 4, 5 ] inter [ 3, 4 ] A-B [ 1, 2 ] sym [ 1, 2, 5 ]
|A u B| = 5 = |A| + |B| - |A n B| = 5
```

`sym` is the **symmetric difference**, elements in exactly one of the two sets. It is the set version of
exclusive or.

**Realistic: bit-string sets.** With U as the days Monday to Sunday, the weekdays are `0b1111100` and the
days a shop is open are `0b0111110` (Tuesday to Saturday). Open weekdays are the AND, `0b0111100`,
Tuesday to Friday. Days that are a weekday or open are the OR, `0b1111110`.

**Realistic: a survey.** 120 people use a CI tool A, 90 use B, and 40 use both. People using at least one
are 120 plus 90 minus 40, which is 170.

### Common mistake

**Forgetting to fix the universe.** The wrong way: "the complement of the set of admins is the set of
non-admin users" when the query also returns deleted accounts and service accounts. Why it fails: the
complement is taken in U, and U was not the set you had in mind.

The fix is to name U explicitly before taking any complement. In SQL, `NOT IN` against a subquery that
returns a `NULL` returns no rows at all, which is the same bug with a nastier twist: the universe
included an unknown.

### In real systems

SQL's `UNION`, `INTERSECT` and `EXCEPT` are these operations on tables. Permission systems compute
effective rights as a union of role grants minus explicit denials. Bitmap indexes in analytical databases
store each column value as a bit-string set and answer `WHERE` clauses with AND and OR over billions of
rows.

Inclusion-exclusion shows up in metrics. Daily active users across web and mobile is not web plus mobile;
it is web plus mobile minus users on both, and dashboards that add the two overcount.

## 2.3 Functions

### In one sentence

A function assigns to every element of one set exactly one element of another, and whether it is
one-to-one, onto, or both decides whether it can be undone.

### The idea

#### Definition

A **function** f from A to B, written f: A → B, assigns exactly one element of B to each element of A.
A is the **domain**, B is the **codomain**. If f(a) is b, then b is the **image** of a and a is a
**preimage** of b. The set of all images is the **range**, a subset of the codomain.

Two parts of the definition do the work. "Each element of A" means no input is left out. "Exactly one"
means no input gets two outputs. Formally a function is a subset of A × B with exactly one pair for each
a.

Two functions are equal when they have the same domain, the same codomain, and agree on every input. So
the squaring function from Z to Z and the squaring function from Z to N are different functions, even
with the same rule.

#### Adding and multiplying functions

For real-valued functions f and g with the same domain, f plus g is the function taking x to f(x) plus
g(x), and f times g takes x to f(x) times g(x). The **image of a subset** S of the domain, f(S), is the
set of images of elements of S.

#### One-to-one

f is **one-to-one**, or **injective**, when different inputs always give different outputs: ∀a ∀b
(f(a) equals f(b) → a equals b). The contrapositive form, a ≠ b → f(a) ≠ f(b), is how people usually
think of it.

A function on reals is **increasing** if x less than y implies f(x) at most f(y), and **strictly
increasing** if it implies f(x) less than f(y). Strictly increasing or strictly decreasing functions are
one-to-one.

#### Onto

f is **onto**, or **surjective**, when every element of the codomain is hit: ∀b ∃a (f(a) equals b). The
range equals the codomain. Whether a rule is onto depends on the codomain you declared.

#### Bijections

f is a **bijection**, or **one-to-one correspondence**, when it is both one-to-one and onto. Every
element of B is hit by exactly one element of A. The **identity function** on A, which maps each element
to itself, is the simplest bijection.

#### Inverses and composition

If f is a bijection, its **inverse** f⁻¹: B → A sends each b back to the unique a with f(a) equal to b.
A function that is not a bijection has no inverse in this sense: if not one-to-one, f⁻¹(b) would have
two answers; if not onto, some b would have none. f is **invertible** exactly when it is a bijection.

The **composition** f ∘ g, read "f of g", is the function taking x to f(g(x)). It needs the range of g
inside the domain of f. Composition is usually not commutative: f ∘ g and g ∘ f differ. Composing f
with its inverse in either order gives the identity.

#### Graphs of functions

The **graph** of f is the set of pairs (a, f(a)). For a real function it is the familiar curve. Reading
injectivity off a graph is the horizontal line test: no horizontal line meets the graph twice.

#### Floor and ceiling

The **floor** of x, ⌊x⌋, is the largest integer at most x. The **ceiling**, ⌈x⌉, is the smallest integer
at least x. They differ only when x is not an integer, and then by exactly 1.

Useful facts, for integer n and real x: ⌊x⌋ equals n iff n ≤ x less than n plus 1; ⌊x plus n⌋ equals
⌊x⌋ plus n; ⌊−x⌋ equals −⌈x⌉. Floor and ceiling turn up whenever things come in whole units: bytes,
pages, packets, rows.

#### The factorial and partial functions

The **factorial** function n! is the product 1 times 2 times ... times n, with 0! equal to 1. It grows
faster than any exponential with a fixed base, a fact chapter 3 uses.

A **partial function** f from A to B assigns at most one element of B to each element of a subset of A,
its domain of definition. Square root on the integers is partial: defined on 0, 1, 4, 9, undefined
elsewhere. Functions that can throw, or return `undefined`, are partial functions in code.

### Worked example

**Simple: classifying functions on finite sets.**

```ts
function kind(dom: number[], cod: number[], f: (x: number) => number) {
  const imgs = dom.map(f);
  const inj = new Set(imgs).size === dom.length;
  const sur = cod.every(y => imgs.includes(y));
  return { inj, sur, bij: inj && sur };
}
console.log('x mod 3 on 0..5 -> 0..2:', kind([0,1,2,3,4,5],[0,1,2], x => x % 3));
console.log('2x on 0..3 -> 0..7:', kind([0,1,2,3],[0,1,2,3,4,5,6,7], x => 2*x));
console.log('x+1 mod 4 on 0..3 -> 0..3:', kind([0,1,2,3],[0,1,2,3], x => (x+1)%4));
```

```text
x mod 3 on 0..5 -> 0..2: { inj: false, sur: true, bij: false }
2x on 0..3 -> 0..7: { inj: true, sur: false, bij: false }
x+1 mod 4 on 0..3 -> 0..3: { inj: true, sur: true, bij: true }
```

`inj` checks that no two inputs share an output by comparing the number of distinct images with the
number of inputs. `sur` checks that every codomain value is an image. The last function rotates 0, 1, 2,
3, so it is a bijection; its inverse subtracts 1 mod 4.

**Simple: floor and ceiling in code.**

```ts
console.log('floor/ceil:', Math.floor(-2.5), Math.ceil(-2.5), Math.trunc(-2.5), Math.floor(2.5), Math.ceil(2.5));
console.log('pages for 101 items at 20 per page:', Math.ceil(101 / 20));
```

```text
floor/ceil: -3 -2 -2 2 3
pages for 101 items at 20 per page: 6
```

Note `Math.trunc(-2.5)` is −2, not −3. Truncation rounds toward zero, floor rounds down, and they agree
only for non-negative numbers.

**Realistic: user IDs to shard numbers.** `shard(id) = hash(id) % 16` is a function from IDs to 0 to 15.
It is not one-to-one, by design; many users share a shard. It should be onto, or a shard sits idle. If
it is also roughly balanced, each shard gets about a sixteenth of the users.

    ["6", "Let x be (y minus 4) divided by 3, which is real.", "solve 3x plus 4 equals y for x"],
    ["7", "f(x) is 3 times (y minus 4)/3 plus 4, which is y.", "check the construction"],
    ["8", "So f is onto, and a bijection, with inverse y to (y minus 4)/3.", "lines 4 and 7"],
  ]}
  caption="Proving a bijection. The one-to-one half runs backwards from equal outputs to equal inputs; the onto half constructs a preimage, and that construction is the inverse."
/>

And a disproof: f: Z → Z, f(x) equals x², is neither. Not one-to-one, because f(2) equals f(−2). Not
onto, because no integer squares to 3. One witness each is enough.

### Common mistake

**Forgetting the codomain.** The wrong claim: "x squared is onto". Over R → R, it is not, because −1 is
never hit. Over R → R⁺ together with 0, it is. The rule is the same; the codomain changes the answer.

The fix is to write f: A → B every time, with both sets, before asking any of these questions. In
TypeScript, the return type is the codomain, and a function typed `number → number` that only returns
non-negative values is not onto `number`.

### In real systems

Pure functions in code are functions in this exact sense when they are total and deterministic.
Encodings must be bijections to round-trip: base64 encoding and decoding compose to the identity, and a
lossy encoding such as lowercasing usernames is not one-to-one, which is how two accounts collide.

Hash functions are deliberately not one-to-one, which is why collisions exist and why a hash table must
handle them. Database primary keys are one-to-one maps from rows to keys. Pagination uses ceiling:
`Math.ceil(total / pageSize)` pages, and an off-by-one there is a ceiling-versus-floor bug.

## 2.4 Sequences and summations

### In one sentence

A sequence is a function on the integers that lists terms in order, and a summation adds a stretch of
them, often with a closed form that replaces the loop with one formula.

### The idea

#### Sequences

A **sequence** is a function from a subset of the integers, usually 0, 1, 2 and on, or 1, 2, 3 and on,
to a set S. The value at n is written aₙ and called a **term**. A finite list of terms is also called a
**string**, and the string with no terms is the **empty string**, of length 0.

#### Arithmetic and geometric progressions

A **geometric progression** has the form a, ar, ar², ..., where a is the initial term and r the
**common ratio**. An **arithmetic progression** has the form a, a plus d, a plus 2d, ..., where d is the
**common difference**. These are the discrete versions of exponential and linear functions.

#### Recurrence relations

A **recurrence relation** defines aₙ in terms of earlier terms. **Initial conditions** fix the first
terms. Together they determine the sequence. The **Fibonacci sequence** has f0 equal to 0, f1 equal to 1,
and fₙ equal to fₙ₋₁ plus fₙ₋₂.

**Solving** a recurrence means finding a **closed formula**, a formula for aₙ that does not refer to
earlier terms. **Iteration** finds one by unrolling: substitute the recurrence into itself until a
pattern appears. Chapter 8 gives systematic methods.

#### Compound interest as a recurrence

If a deposit earns 11 percent a year, the balance satisfies Pₙ equals 1.11 times Pₙ₋₁. Unrolling gives
Pₙ equals 1.11 to the n times P0. This is a geometric progression; the recurrence and the closed form
describe the same thing.

#### Special sequences and guessing a rule

Given the first terms, finding a rule means asking: are terms the same? Is each obtained from the
previous by adding or multiplying a fixed amount? By combining earlier terms? Do they match a known
sequence such as squares, cubes, powers of 2, factorials or Fibonacci numbers? The **On-Line
Encyclopedia of Integer Sequences** (OEIS) is the standard lookup.

A finite list of terms never determines the rule uniquely. Infinitely many formulas match any finite
start, so a guessed rule is a conjecture until proved.

#### Summation notation

**Sigma notation** writes the sum of aₘ, aₘ₊₁, ..., aₙ as Σ from j equals m to n of aⱼ. j is the **index
of summation**, m the **lower limit**, n the **upper limit**. The index is a dummy variable, like the
loop variable in a `for` loop, and renaming it changes nothing.

Sums are linear: Σ (c aⱼ plus bⱼ) equals c Σ aⱼ plus Σ bⱼ. The index can be **shifted**: Σ from j equals 1
to 5 of j² equals Σ from k equals 0 to 4 of (k plus 1)².

#### The geometric series formula

For r not 1, the sum of a rʲ for j from 0 to n is (a rⁿ⁺¹ minus a) divided by (r minus 1). For r equal to
1 it is (n plus 1) a. The derivation is the most useful trick in the section; it is walked through below.

#### Double sums and other closed forms

A **double sum** is a sum of sums, evaluated from the inside out, like nested loops. Common closed forms:

| Sum | Closed form |
|---|---|
| k from 1 to n | n(n plus 1)/2 |
| k² from 1 to n | n(n plus 1)(2n plus 1)/6 |
| k³ from 1 to n | n²(n plus 1)²/4 |
| a rᵏ from 0 to n, r not 1 | a (rⁿ⁺¹ minus 1)/(r minus 1) |
| xᵏ from 0 to infinity, absolute x less than 1 | 1/(1 minus x) |

Sums can also run over the elements of a set: Σ over s in S of f(s). The order does not matter for a
finite set.

### Worked example

**Simple: checking the closed forms in code.**

```ts
let s = 0; for (let k = 1; k <= 100; k++) s += k;
console.log('sum 1..100 =', s, 'formula', 100 * 101 / 2);
let g = 0; for (let k = 0; k <= 10; k++) g += 3 * 2 ** k;
console.log('sum 3*2^k k=0..10 =', g, 'formula', 3 * (2 ** 11 - 1));
let sq = 0; for (let k = 1; k <= 10; k++) sq += k * k;
console.log('sum k^2 1..10 =', sq, 'formula', 10 * 11 * 21 / 6);
let dbl = 0; for (let i = 1; i <= 4; i++) for (let j = 1; j <= 3; j++) dbl += i * j;
console.log('double sum =', dbl);
```

```text
sum 1..100 = 5050 formula 5050
sum 3*2^k k=0..10 = 6141 formula 6141
sum k^2 1..10 = 385 formula 385
double sum = 60
```

The double sum is Σ over i from 1 to 4 of Σ over j from 1 to 3 of ij. The inner sum is 6i, and Σ 6i for
i from 1 to 4 is 60. Nested loops and nested sums are the same thing.

**Realistic: loop costs.** A loop `for i in 0..n, for j in 0..i` does Σ i for i from 0 to n minus 1, which
is n(n minus 1)/2 inner steps. That closed form is why "compare every pair" is quadratic.

**Realistic: retry backoff.** Retries with waits of 100 ms, 200 ms, 400 ms and so on, 6 retries, wait in
total 100 times (2⁶ minus 1), which is 6,300 ms. The geometric series answers "how long can a request
hang?" in one line.

**Realistic: floating-point sums.**

```ts
let f = 0.0; for (let i = 0; i < 10; i++) f += 0.1;
console.log('ten 0.1s:', f);
```

```text
ten 0.1s: 0.9999999999999999
```

Mathematically the sum is 1. In floating point each addition rounds, and errors accumulate. Money is
summed in integer paise, not in floating rupees, for this reason.

formula, and test with n equal to 1 and 2.

### In real systems

Every complexity analysis of nested loops is a summation. Amortised analysis of dynamic arrays uses the
geometric series: doubling capacity costs 1 plus 2 plus 4 plus ... plus n copies, which is under 2n, so
appends are constant time on average.

Recurrences describe interest, population models, and the cost of recursive algorithms. Floating-point
summation error is real in analytics pipelines; Kahan summation or integer units are the fixes.

## 2.5 Cardinality of sets

### In one sentence

Two sets have the same size exactly when a bijection pairs them up, and with that definition some
infinite sets, like the reals, turn out to be strictly bigger than others, like the integers.

### The idea

#### Size without counting

For finite sets, counting works. For infinite sets it does not, so size is defined by pairing. Sets A
and B have the **same cardinality**, |A| equals |B|, when there is a bijection from A to B. If there is a
one-to-one function from A to B, then |A| ≤ |B|. If |A| ≤ |B| and the sizes differ, |A| is less than |B|.

This is how a child compares two piles of sweets without numbers: pair them off one by one and see which
pile has leftovers.

#### Countable sets

A set is **countable** if it is finite or has the same cardinality as Z⁺. An infinite countable set is
**countably infinite**, and its cardinality is called **aleph null**, written ℵ0. A set that is not
countable is **uncountable**.

Countably infinite means the elements can be listed as a sequence a1, a2, a3, ... with every element
appearing at some finite position. That listing is the bijection from Z⁺.

#### Surprising countable sets

The positive odd integers are countable: n maps to 2n minus 1. The integers are countable: list them as
0, 1, −1, 2, −2, and so on. A proper subset of an infinite set can have the same size as the whole,
which never happens for finite sets.

The positive rationals are countable too. Arrange p/q in a grid with p as the row and q as the column,
then walk the diagonals where p plus q is constant, skipping fractions not in lowest terms. Every
positive rational sits on some diagonal, so it appears at some finite step.

#### Hilbert's Grand Hotel

The book's story: a hotel with countably many rooms, all full. A new guest arrives. Move the guest in
room n to room n plus 1, and room 1 is free. Countably many new guests arrive: move room n to room 2n,
and every odd room is free. Infinite sets absorb additions without growing.

#### The reals are uncountable

**Cantor's diagonal argument** shows the reals between 0 and 1 cannot be listed. Suppose a list r1, r2,
r3, ... contained all of them, as decimals. Build a new number d whose i-th digit differs from the i-th
digit of rᵢ. Then d differs from every rᵢ in at least one place, so d is not in the list. Contradiction.

So |Z⁺| is less than |R|. The real numbers form a strictly larger infinity, called the cardinality of
the **continuum**, written c.

#### Results about cardinality

A subset of a countable set is countable. A union of two countable sets is countable, and so is a
countable union of countable sets. The **Schröder-Bernstein theorem** says that if there are one-to-one
functions from A to B and from B to A, then there is a bijection, so |A| equals |B|. It lets you prove
equal size without building the bijection directly.

#### Uncomputable functions

Every computer program is a finite string over a finite alphabet, so the set of programs is countable.
The set of functions from Z⁺ to the digits 0 to 9 is uncountable, by a diagonal argument. So most
functions are **uncomputable**: no program computes them. Chapter 3's halting problem is a specific
example.

#### The continuum hypothesis

The **continuum hypothesis** asks whether there is a set strictly bigger than Z⁺ and strictly smaller
than R. It was shown to be neither provable nor disprovable from the standard axioms of set theory. It is
one of the few places this book touches the limits of proof itself.

### Worked example

**Simple: the diagonal on a finite list, in code.**

```ts
const list = ['0101', '1100', '0010', '1111'];
const diag = list.map((s, i) => (s[i] === '0' ? '1' : '0')).join('');
console.log('diagonal string', diag, 'in list?', list.includes(diag));
```

```text
diagonal string 1000 in list? false
```

The new string flips the first bit of the first string, the second bit of the second, and so on, so it
differs from each one somewhere. For a finite list this is just a way to find a missing string. For an
infinite list, it proves no list can be complete.

**Simple: walking the rationals.**

```ts
const gcd = (a: number, b: number): number => (b === 0 ? a : gcd(b, a % b));
const rats: string[] = [];
for (let sum = 2; rats.length < 11; sum++)
  for (let p = 1; p < sum && rats.length < 11; p++) {
    const q = sum - p;
    if (gcd(p, q) === 1) rats.push(`${p}/${q}`);
  }
console.log('first rationals:', rats.join(' '));
```

```text
first rationals: 1/1 1/2 2/1 1/3 3/1 1/4 2/3 3/2 4/1 1/5 5/1
```

Each pass of the outer loop is one diagonal, p plus q equal to `sum`. Fractions such as 2/2 and 2/4 are
skipped because they repeat earlier ones, so the listing is a bijection.

**Realistic: ID spaces.** A system that assigns every user a positive integer ID is a one-to-one map into
Z⁺, so the set of possible users of any program is at most countable. Every string a program can produce
is countable. That is why "a list of all possible inputs" exists conceptually for strings but not for
real-valued sensor readings.

the same cardinality. The fix is to use only the bijection definition and never intuition from finite
sets.

### In real systems

Countability is why a program can enumerate all strings, all programs and all finite graphs, which is
the basis of brute-force search and fuzzing. Uncountability, and the uncomputable functions that follow,
is why some questions about programs, such as "does this program ever crash?", cannot be answered by any
tool in general. Static analysers approximate instead.

Floating-point numbers are a finite subset of the reals. Most reals have no exact representation, which
is the practical shadow of uncountability.

## 2.6 Matrices

### In one sentence

A matrix is a rectangular array of numbers with rules for adding and multiplying, and its product,
including the Boolean version, combines rows of one with columns of the other.

### The idea

#### Definitions

A **matrix** is a rectangular array of numbers. An m × n matrix has m rows and n columns. It is
**square** when m equals n. Two matrices are **equal** when they have the same shape and the same entry
in every position. The entry in row i, column j of A is written aᵢⱼ, and A is written [aᵢⱼ].

#### Sum

The **sum** of two m × n matrices adds entry by entry: (A plus B)ᵢⱼ is aᵢⱼ plus bᵢⱼ. Matrices of different
shapes cannot be added.

#### Product

If A is m × k and B is k × n, the **product** AB is m × n, with entry (i, j) equal to the sum over t of
aᵢₜ bₜⱼ. In words: row i of A dotted with column j of B. The inner sizes must match.

The product is **associative**, (AB)C equals A(BC), and **not commutative**: AB and BA usually differ, and
one may be defined when the other is not.

#### Cost of multiplication

Computing AB for A of size m × k and B of size k × n takes m times k times n multiplications with the
direct method. For two n × n matrices that is n³. When multiplying a chain of matrices, the order of
multiplication changes the cost a lot, though not the answer; chapter 8's dynamic programming finds the
best order.

#### Identity and powers

The **identity matrix** Iₙ has 1s on the diagonal and 0s elsewhere. AIₙ equals A and IₘA equals A. For a
square A, the **powers** are A⁰ equal to I, and Aʳ equal to A times A times ... (r times).

#### Transpose and symmetric matrices

The **transpose** Aᵗ swaps rows and columns: (Aᵗ)ᵢⱼ is aⱼᵢ. A square matrix is **symmetric** when it
equals its transpose. The adjacency matrix of an undirected graph is symmetric.

#### Zero-one matrices

A **zero-one matrix** has only 0s and 1s. Its operations use Boolean arithmetic. The **join** A ∨ B is
entrywise OR; the **meet** A ∧ B is entrywise AND. The **Boolean product** A ⊙ B has entry (i, j) equal to
the OR over t of (aᵢₜ AND bₜⱼ): 1 exactly when some t has a 1 in both row i of A and column j of B.

Boolean powers A to the r with the Boolean product are defined the same way. Chapter 9 uses them for
reachability in relations, and chapter 10 for paths in graphs.

last digits; compare with a tolerance.

### In real systems

Matrices are the data layout of graphics (transform matrices), machine learning (weights and batches),
recommendation (user-by-item matrices), and search ranking. GPU kernels and BLAS libraries are optimised
matrix multiplication.

Zero-one matrices are graph and relation storage. A dense adjacency matrix uses n² bits and answers "is
there an edge" in constant time; an adjacency list uses space proportional to the edges. Phase 3 of the
roadmap makes that trade-off for real.

## From beginner to strategy

<Levels label="Chapter 2, Basic Structures: Sets, Functions, Sequences, Sums, and Matrices">
<Level name="Beginner" depth={3}>

The smallest working version: a set is a bag of distinct things where order does not matter; a function
gives every input exactly one output; a sequence is a numbered list; a sum adds a stretch of it; a matrix
is a table of numbers.

Worked example: the set of people in a meeting, a function from each person to their team, the sequence
of meeting dates, the sum of their durations this month, and a matrix of who-reviewed-whose code. Five
structures, one ordinary situation.

The beginner mistake is treating a set like a list, expecting order or duplicates to matter. The fix is
to ask, "if I shuffle this or repeat an element, is it still the same thing?" If yes, it is a set.

</Level>
<Level name="Intermediate" depth={3}>

At this level the structures combine in code. Sets answer membership and deduplication, functions map
records to keys, sums give totals and costs, and matrices hold pairwise data.

Example: compute, for a team, which pairs of people have both reviewed each other's code. With a
reviewer-by-author zero-one matrix R, the meet of R and its transpose has a 1 at (i, j) exactly when i
reviewed j and j reviewed i.

```ts
const R = [[0, 1, 1], [1, 0, 0], [0, 1, 0]];
const Rt = R[0].map((_, j) => R.map(r => r[j]));
const mutual = R.map((r, i) => r.map((x, j) => x & Rt[i][j]));
console.log(JSON.stringify(mutual));
```

```text
[[0,1,0],[1,0,0],[0,0,0]]
```

People 1 and 2 reviewed each other. The mistake is computing this with nested loops over names and
missing a pair because a name was misspelt; the fix is to map names to indices with a bijection first.

</Level>
<Level name="Advanced" depth={3}>

Underneath are exact definitions. Set equality is ∀x (x ∈ A ↔ x ∈ B). A function is a subset of A × B
with exactly one pair per input. Same cardinality means a bijection exists. A matrix product is a double
sum with a fixed index pattern.

Example: proving |P(A)| equals 2 to the n with a bijection. Map each subset S of A, with A ordered as
a1 to an, to the bit string whose i-th bit is 1 iff aᵢ ∈ S. Different subsets give different strings,
and every string is the image of the subset it describes, so this is a bijection onto the 2ⁿ bit strings.

The mistake at this level is "proving" a bijection by showing only one-to-one, or only onto. The fix is
to prove both, or to exhibit an inverse and check both compositions are identities.

</Level>
<Level name="Edge cases" depth={3}>

- **Empty set.** |∅| is 0, P(∅) has one element, ∅ × A is ∅ for every A, and the empty union is ∅.
- **Singleton domain.** A function from a one-element set is always one-to-one; it is onto only if the
  codomain also has one element.
- **Empty sum.** A sum whose upper limit is below its lower limit is 0, and an empty product is 1. That
  is why 0! is 1.
- **1 × 1 matrices.** They behave like numbers and commute; non-commutativity first appears at 2 × 2.
- **Negative floor.** ⌊−2.5⌋ is −3, not −2. `Math.trunc` and `Math.floor` disagree here.
- **Geometric series with r equal to 1.** The formula divides by zero; the sum is (n plus 1)a.

The mistake is assuming the general formula covers these. The fix is a test per bullet.

</Level>
<Level name="Corner cases" depth={3}>

- **Empty set plus complement.** The complement of ∅ is U, so the answer depends entirely on which U was
  fixed. Two services with different U disagree on "all users not in the blocklist".
- **Infinite set plus "one-to-one implies onto".** True for finite sets of equal size, false for N to N
  with n mapped to n plus 1. Code that relies on the finite version, such as a perfect hash over a
  growing key set, breaks when the set grows.
- **Floor plus negative division.** In JavaScript, `-7 % 3` is −1, while the mathematical remainder is 2.
  `Math.floor(-7 / 3)` is −3 and agrees with the maths; `Math.trunc` gives −2.
- **Matrix product plus floating point.** Associativity holds in exact arithmetic and fails in the last
  digits in floating point; reordering a chain for speed changes the output slightly.
- **Set of objects plus mutation.** Mutating an object inside a JavaScript `Set` changes its contents
  without changing its identity, so two "different" elements can end up equal by value.

Each is two boundaries at once. The fix is to write the specific input into a test.

</Level>
<Level name="Production level" depth={3}>

In production these structures run at scale. Set operations on millions of IDs need hashing or sorted
merges; bitmap sets compress well when IDs are dense. Functions used as keys, such as hashing for
sharding, must be onto the shards and balanced, or one shard melts.

Sums at scale meet floating-point error and overflow: summing a billion values in single precision loses
digits, and integer counters overflow 32 bits at about 2.1 billion. Matrix work moves to libraries that
use the hardware well, and the shape check in `mul` above is exactly the error message a numerical
library throws.

The mistake is writing these by hand in hot paths. The fix is to know the definitions well enough to
choose and test the right library call, and to measure.

</Level>
<Level name="Mindset" depth={3}>

The habit this chapter teaches is to name the structure before writing the code. "Is this a set, a
sequence or a function?" decides the data structure, the operations and the bugs.

The second habit is to check the boundaries of a definition: domain and codomain for functions, the
universe for complements, limits for sums, shapes for matrices. Most errors with these structures are at
the boundaries, not in the middle.

Example outside maths: a product requirement "show users their recent orders" hides a function (user to
orders), a sequence (orders sorted by time), and a set operation (minus cancelled orders). Naming them
makes the edge cases (no orders, ties in time) obvious before code exists.

</Level>
<Level name="System design" depth={3}>

In a larger system, sets become indexes and caches, functions become services and keys, sums become
aggregations, and matrices become feature stores and graph adjacency.

Concrete system: a recommendation service. Users and items are sets; interactions form a user-by-item
matrix; a recommendation is a function from users to ranked sequences of items; and total exposure per
item is a sum over users. The design choices, a sparse matrix versus dense, a precomputed function versus
computed on request, are choices about these structures.

The mistake is picking storage before knowing which operations dominate. The fix is to list the
operations as set, function and matrix operations, estimate their sizes with the summation formulas, and
choose storage from that.

</Level>
<Level name="Strategy" depth={3}>

I learn this chapter by implementing each structure in a small TypeScript module and testing it against
its definition. Sets: union, intersection, difference, complement, power set, product. Functions:
injective, surjective, inverse, compose. Sums: loop versus closed form. Matrices: sum, product, transpose,
Boolean product, power.

Then I prove three identities by hand, one per method: membership, membership table and laws. And I
rewrite the diagonal argument from a blank page, because it is the idea in this chapter I will meet again
in chapter 3 and in computability.

Done when every function in my module passes property tests against brute force on small random inputs,
and I can explain why the rationals are countable and the reals are not without notes.

</Level>
</Levels>

## Questions people ask

**why does the book include 0 in N?**

It is a convention, and computer science usually includes 0 because indices and counts start there.
Check the convention whenever you read another book.

**is a function the same as a TypeScript function?**

A total, deterministic TypeScript function without side effects is a function in this sense. One that
throws on some inputs is a partial function. One that depends on time or randomness is not a function of
its arguments alone.

**why should a programmer care about uncountable sets?**

Because they explain why most problems about programs cannot be solved by programs: there are countably
many programs and uncountably many functions. It is the root of the halting problem in chapter 3.

**are matrices here the same as in linear algebra?**

Yes, with less theory. Rosen covers arithmetic and zero-one matrices because discrete maths needs them
for relations and graphs. Linear algebra adds vector spaces, determinants and eigenvalues.

## Key takeaways

- A set is determined by its members alone; order and repetition do not matter.
- Set operations mirror logical connectives, so every set identity is a logical equivalence.
- Prove set equality by two inclusions, by a membership table, or by the laws.
- A function needs exactly one output per input; one-to-one, onto and bijection depend on the declared
  codomain.
- Only bijections have inverses; composition is usually not commutative.
- Sums are loops with closed forms; the geometric series comes from shifting and subtracting.
- Same size means a bijection; Z and Q are countable, R is not, by the diagonal argument.
- Matrix products need matching inner sizes, are associative and are not commutative; Boolean products
  compute reachability.

## Glossary

- **Set, element**: an unordered collection of distinct objects; one of its members.
- **Roster method, set builder notation**: listing elements; describing them by a rule.
- **Subset, proper subset**: every element is also in the other set; and the sets differ.
- **Empty set, singleton**: the set with no elements; a set with exactly one.
- **Cardinality**: the number of elements of a finite set; more generally, size by bijection.
- **Power set**: the set of all subsets.
- **Ordered n-tuple**: a list where order matters.
- **Cartesian product**: the set of ordered pairs from two sets.
- **Truth set**: the elements of a domain for which a predicate is true.
- **Union, intersection, difference, complement**: or, and, in-the-first-but-not-the-second, not-in-the-set.
- **Universal set**: the set of everything under discussion.
- **Disjoint**: sets with empty intersection.
- **Symmetric difference**: elements in exactly one of two sets.
- **Membership table**: a truth table for set identities.
- **Function, domain, codomain, range**: a rule giving one output per input; inputs; allowed outputs; actual outputs.
- **Image, preimage**: the output of an element; an input mapping to a given output.
- **One-to-one (injective), onto (surjective), bijection**: no shared outputs; every output hit; both.
- **Inverse function, composition**: undoing a bijection; applying one function after another.
- **Floor, ceiling**: round down to an integer; round up.
- **Factorial**: the product 1 times 2 up to n, with 0! equal to 1.
- **Partial function**: defined on only part of its domain.
- **Sequence, term, string**: a function on integers; one of its values; a finite sequence.
- **Arithmetic, geometric progression**: constant difference; constant ratio.
- **Recurrence relation, initial conditions, closed formula**: terms from earlier terms; the first terms; a formula without earlier terms.
- **Summation notation, index of summation**: sigma notation; the loop variable of a sum.
- **Countable, countably infinite, uncountable**: finite or the size of Z⁺; the size of Z⁺; bigger than Z⁺.
- **Diagonal argument**: building an element that differs from the i-th listed element in place i.
- **Schröder-Bernstein theorem**: one-to-one maps both ways imply a bijection.
- **Uncomputable function**: a function no program computes.
- **Matrix, square matrix, identity matrix**: a rectangular array; with equal rows and columns; 1s on the diagonal.
- **Transpose, symmetric matrix**: rows and columns swapped; equal to its transpose.
- **Zero-one matrix, join, meet, Boolean product**: entries 0 or 1; entrywise OR; entrywise AND; OR of ANDs.
