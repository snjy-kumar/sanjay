Counting is the part of discrete maths that answers "how many?" without listing everything: how many
passwords, how many test cases, how many ways a schedule can go wrong. This chapter builds the counting
toolkit from two simple rules up to combinations with repetition, and every later chapter on probability,
graphs and algorithms leans on it.

## 6.1 The basics of counting

### In one sentence

If a task is a sequence of independent steps, multiply the number of ways for each step; if it is a
choice between disjoint alternatives, add them; and correct for overlap or for counting things more than
once.

### The idea

#### The product rule

If a procedure is a sequence of two tasks, with n1 ways to do the first and, for each of those, n2 ways
to do the second, then there are n1·n2 ways to do the procedure. It extends to any number of tasks.

A code made of three letters followed by three digits has 26·26·26·10·10·10 choices, which is
17,576,000. A 32-bit value has 2³² possibilities, 4,294,967,296. In set terms, the product rule is
|A1 × A2 × ... × Aₘ| equal to |A1|·|A2|·...·|Aₘ|.

#### Counting functions

Functions from a set of size m to a set of size n: each of the m elements independently picks one of n
values, so nᵐ functions. **One-to-one** functions: the first element has n choices, the next n minus 1,
and so on, so n(n minus 1)...(n minus m plus 1), which is zero if m is greater than n. From 3 elements to
5 there are 125 functions and 60 one-to-one ones.

A set with n elements has 2ⁿ subsets, because each element is in or out: a bit string of length n.

#### The sum rule

If a task can be done in one of n1 ways or one of n2 ways, and no way is in both groups, there are n1
plus n2 ways. In set terms, for disjoint sets, |A ∪ B| equals |A| plus |B|.

Most real problems combine the two. Passwords of 4 to 6 characters from lowercase letters and digits, with
at least one digit: for each length n, all strings minus all-letter strings, 36ⁿ minus 26ⁿ, then add the
three lengths.

#### The subtraction rule

If a task can be done in n1 ways or n2 ways, and some ways are in both, the total is n1 plus n2 minus the
number in both. This is **inclusion–exclusion** for two sets: |A ∪ B| equals |A| plus |B| minus |A ∩ B|.
Chapter 8 extends it to any number of sets.

#### The division rule

If a procedure can be done in n ways, and every outcome is produced by exactly d of those ways, there are
n/d outcomes. Seating 5 people round a circular table: 5! linear orders, but each seating appears 5 times
under rotation, so 4!, which is 24.

#### Tree diagrams

When choices depend on earlier choices, draw a **tree**: each branch is a choice and each leaf is an
outcome. Count the leaves. Bit strings of length 4 with no two consecutive 1s: after a 1 the only branch
is 0.

### Worked example

**Simple: counting with code.**

```ts
console.log(26 ** 3 * 10 ** 3, 2 ** 32);
let total = 0;
for (const n of [4, 5, 6]) total += 36 ** n - 26 ** n;
console.log('4-6 chars, at least one digit:', total);
console.log('functions 3 to 5:', 5 ** 3, 'one-to-one:', 5 * 4 * 3);
```

```text

```

**Realistic: subtraction rule.** How many bit strings of length 10 start with 1 or end with 0? Start with
1: 2⁹, 512. End with 0: 512. Both: 2⁸, 256. So 512 plus 512 minus 256, which is 768.

**Realistic: test matrix.** A service runs on 3 operating systems, 4 runtime versions and 2 database
engines. A full test matrix is 3·4·2, which is 24 jobs. Adding a second region doubles it to 48. Counting
first is how you notice a matrix is about to explode.

### Common mistake

**Adding overlapping cases.** The wrong way: "strings that start with 1 plus strings that end with 0"
giving 1,024 for length 10. Why it fails: strings that do both are counted twice.

The fix is the subtraction rule, or splitting into disjoint cases before adding.

**Multiplying dependent choices as if independent.** Choosing a president and vice-president from 10
people is 10·9, not 10·10. The fix is to count each step's options *given* the earlier steps.

### In real systems

Counting sizes search spaces: the number of keys an attacker must try, the number of states a model
checker must explore, the number of configurations a test matrix covers. Password policies, ID formats
and URL shorteners are designed by counting: a 7-character base-62 code gives 62⁷, about 3.5 trillion IDs.

## 6.2 The pigeonhole principle

### In one sentence

If more than k objects go into k boxes, some box gets at least two, and more generally if N objects go
into k boxes, some box gets at least the ceiling of N/k.

### The idea

#### The basic principle

If k plus 1 or more objects are placed into k boxes, at least one box contains two or more objects.
Proof by contradiction: if every box had at most one, there would be at most k objects.

A function from a set of k plus 1 elements to a set of k elements cannot be one-to-one. Among 13 people,
two share a birth month.

#### The generalised principle

If N objects are placed into k boxes, some box contains at least ⌈N/k⌉ objects. Proof: if every box had
at most ⌈N/k⌉ minus 1, the total would be less than k·(N/k plus 1 minus 1), which is N.

Among 100 people at least ⌈100/12⌉, which is 9, share a birth month. To guarantee 3 share a birth month
you need 2·12 plus 1, which is 25 people.

#### Clever uses

The skill is choosing the pigeons and the boxes. Some standard moves:

- **Remainders as boxes.** Among any n plus 1 integers, two have the same remainder mod n, so their
  difference is divisible by n.
- **Prefix sums as pigeons.** In any sequence of n integers, some consecutive block has a sum divisible
  by n: take the n prefix sums mod n; either one is 0 or two are equal, and the block between them works.
- **Monotone subsequences.** Every sequence of n² plus 1 distinct numbers has an increasing or a
  decreasing subsequence of length n plus 1. This is the Erdős–Szekeres theorem.

#### A prefix-sum example, worked

Take the five numbers 3 8 5 9 4 and ask for a consecutive block whose sum is divisible by 5. The running
totals are 3, 11, 16, 25, 29, and mod 5 they are 3, 1, 1, 0, 4. One prefix is 0 mod 5: the first four
numbers sum to 25. Two prefixes are equal, 1 and 1: the block between them, just the 5, works too.

Why it must happen in general: there are n prefix sums and n possible remainders. If none is 0, only n
minus 1 remainders are available for n prefixes, so two collide. Subtracting those two prefixes gives a
block whose sum is 0 mod n.

#### Ramsey numbers

At any party of 6 people, there are 3 mutual friends or 3 mutual strangers. Proof: fix one person; of the
other 5, at least 3 are friends or at least 3 are strangers of that person, by pigeonhole. Say 3 friends.
If any two of them are friends, they and the first person form a friendly triangle; if none are, they
form a stranger triangle.

The **Ramsey number** R(m, n) is the least number of people that guarantees m mutual friends or n mutual
strangers. R(3, 3) is 6: with 5 people, a pentagon of friendships avoids both. Very few Ramsey numbers are
known exactly.

### Worked example

**Simple: pigeonhole arithmetic.**

```ts
console.log(Math.ceil(100 / 12), 'people for 3 in a month:', 2 * 12 + 1);
```

```text
9 people for 3 in a month: 25
```

**Realistic: Erdős–Szekeres on a sequence.** The 10 numbers 6 2 9 4 1 8 3 7 5 10 are n² plus 1 for n
equal to 3, so a monotone subsequence of length 4 must exist.

```ts
function longestInc(a: number[]) {
  const L = a.map(() => 1);
  for (let i = 0; i < a.length; i++)
    for (let j = 0; j < i; j++) if (a[j] < a[i]) L[i] = Math.max(L[i], L[j] + 1);
  return Math.max(...L);
}
const seq = [6, 2, 9, 4, 1, 8, 3, 7, 5, 10];
console.log(longestInc(seq), longestInc(seq.map(x => -x)));
```

```text
4 4
```

Both exist here: 2 4 8 10 is increasing and 9 8 7 5 is decreasing.

**Realistic: R(3, 3) by brute force.** Node checked the pentagon colouring of 5 people: no single-colour
triangle. Then it tried all 2¹⁵, which is 32,768, ways to colour the friendships among 6 people: every one
had a single-colour triangle.

### Common mistake

**Confusing "at least one box has two" with "every box has one".** The wrong way: "13 people, 12 months,
so every month has someone." Why it fails: pigeonhole only guarantees a collision, not coverage.

The fix is to state the conclusion exactly: some box has at least ⌈N/k⌉. Coverage is a different
question, about onto functions.

**Choosing the wrong boxes.** Most pigeonhole proofs fail because the boxes do not force the conclusion.
Ask: if two pigeons share a box, does that give me what I want?

### In real systems

Pigeonhole is why hash collisions are unavoidable: more possible inputs than hash values means some share
a hash. It is why lossless compression cannot shrink every file, since there are fewer shorter files than
files. The birthday version, in chapter 7, says how soon collisions appear: after about √N items.

## 6.3 Permutations and combinations

### In one sentence

An r-permutation is an ordered selection of r distinct elements, counted by n!/(n minus r)!, and an
r-combination is an unordered one, counted by n!/(r!(n minus r)!), because each combination corresponds to
r! permutations.

### The idea

#### Permutations

A **permutation** of a set is an ordered arrangement of its elements. An **r-permutation** is an ordered
arrangement of r of them. By the product rule the number of r-permutations of n elements is
P(n, r) equal to n(n minus 1)...(n minus r plus 1), which is n!/(n minus r)!. P(n, n) is n!, and P(n, 0)
is 1.

Awarding gold, silver and bronze among 8 finalists: P(8, 3), which is 336.

#### Combinations

An **r-combination** is an unordered selection of r elements: an r-element subset. Their number is C(n,
r), also written as n choose r. Every r-combination can be ordered in r! ways, so P(n, r) equals C(n,
r)·r!, which gives C(n, r) equal to n!/(r!(n minus r)!).

Choosing 3 reviewers from 10 engineers: C(10, 3), which is 120. Five-card hands from 52 cards: C(52, 5),
which is 2,598,960.

#### Symmetry

C(n, r) equals C(n, n minus r): choosing which r to take is the same as choosing which n minus r to
leave. So C(52, 47) is also 2,598,960.

#### Combinatorial proofs

A **combinatorial proof** of an identity shows both sides count the same set, either by **double
counting** (counting one set in two ways) or by a **bijective proof** (a one-to-one correspondence
between two sets). The symmetry identity has a bijective proof: send each r-subset to its complement.

#### Arrangements with restrictions

Many permutation problems add a condition. Two standard tricks handle most of them.

**Glue items together.** To count line-ups of 5 people where two particular people stand next to each
other, glue them into one block. There are 4! orders of the 4 units and 2 orders inside the block: 48.
Node confirmed it by brute force over all 120 line-ups. Three maths books that must stay together on a
shelf of 7: 5!·3!, which is 720.

**Count the complement.** Line-ups where the two are *not* adjacent: all minus adjacent, 120 minus 48,
which is 72.

**Lattice paths.** The number of shortest paths on a grid from one corner to the opposite corner, 4 steps
right and 3 steps up, is the number of ways to choose which 3 of the 7 steps go up: C(7, 3), which is 35.
This is a combination in disguise, and many routing and DP problems reduce to it.

#### Combinations as a recursion

C(n, k) can be computed without factorials by Pascal's identity from 6.4, building a table row by row.
That is also how you compute it mod a prime, or when n is large but k is small. The table is the first
taste of dynamic programming: each entry from two smaller ones, each computed once.

### Worked example

**Simple: computing safely.**

```ts
const C = (n: number, r: number) => {
  let x = 1;
  for (let i = 1; i <= r; i++) x = (x * (n - r + i)) / i;
  return Math.round(x);
};
const fact = (n: number): number => (n <= 1 ? 1 : n * fact(n - 1));
console.log(fact(8) / fact(5), C(10, 3), C(52, 5), C(40, 6));
```

```text
336 120 2598960 3838380
```

Computing C(n, r) as a running product avoids the huge factorials; 52! alone has 68 digits.

**Realistic: a committee with structure.** A review board needs 3 of 9 developers and 2 of 6 testers.
Product rule over two independent choices: C(9, 3)·C(6, 2), which is 84·15, which is 1,260.

**Realistic: bit strings.** Bit strings of length 8 with exactly three 1s: choose the 3 positions, C(8,
3), which is 56. With at least one 1: all minus none, 2⁸ minus 1, which is 255.

### Common mistake

**Using permutations when order does not matter.** The wrong way: counting teams of 3 from 10 as P(10, 3),
720. Why it fails: the team A, B, C is the same as C, A, B; each team is counted 6 times.

The fix is to ask "would swapping two chosen items give a different outcome?" If not, use combinations.

**Double counting "at least" problems.** Choosing a 3-person team with at least one senior from 4 seniors
and 6 juniors as "pick a senior, then any 2 others", 4·C(9, 2) equal to 144, overcounts; teams with two
or three seniors are counted more than once. The fix: all teams minus all-junior teams, C(10, 3) minus
C(6, 3), which is 100.

### In real systems

Combinations size feature-flag and configuration testing: with 10 boolean flags, all pairs of flags are
C(10, 2), which is 45, which is why pairwise testing tools cover every pair with far fewer than 2¹⁰ runs.
Permutations size scheduling and ordering searches: 10 jobs have 3,628,800 orders, so brute force stops
being an option quickly.

## 6.4 Binomial coefficients and identities

### In one sentence

The numbers C(n, k) are the coefficients in the expansion of (x plus y)ⁿ, and they satisfy many identities,
Pascal's identity above all, that are easiest to prove by counting the same thing two ways.

### The idea

#### The binomial theorem

For any variables x and y and non-negative integer n, (x plus y)ⁿ is the sum over j from 0 to n of C(n,
j)xⁿ⁻ʲyʲ. Combinatorial proof: expanding the product of n copies of (x plus y), a term xⁿ⁻ʲyʲ arises by
choosing y from j of the n factors and x from the rest, which can be done in C(n, j) ways.

The coefficient of x³y⁴ in (x plus y)⁷ is C(7, 4), which is 35. The coefficient of x²y³ in (2x minus
3y)⁵ is C(5, 3)·2²·(minus 3)³, which is 10·4·(minus 27), which is minus 1,080.

#### Consequences

- Setting x and y to 1: the sum of C(n, k) over k is 2ⁿ, the number of subsets.
- Setting x to 1 and y to minus 1: the alternating sum is 0, so a non-empty set has as many even-sized
  subsets as odd-sized ones.
- Setting x to 1 and y to 2: the sum of 2ᵏC(n, k) is 3ⁿ.

#### Pascal's identity and triangle

**Pascal's identity**: C(n plus 1, k) equals C(n, k minus 1) plus C(n, k), for k between 1 and n.
Combinatorial proof: fix one element a of a set of n plus 1. The k-subsets either contain a, choosing
k minus 1 more from the other n, or do not, choosing all k from the other n.

Arranging the coefficients in rows, each the sum of the two above it, gives **Pascal's triangle**.

#### Vandermonde's identity

C(m plus n, r) equals the sum over k of C(m, r minus k)·C(n, k). Combinatorial proof: to choose r items
from two groups of sizes m and n, choose k from the second and r minus k from the first, for each k. With
m equal to 5, n equal to 4 and r equal to 3, both sides are 84.

A special case: the sum of C(n, k)² over k is C(2n, n). For n equal to 5 both sides are 252.

#### The hockey-stick identity

C(n plus 1, r plus 1) equals the sum of C(j, r) for j from r to n. Combinatorial proof: classify the (r
plus 1)-subsets of 1 to n plus 1 by their largest element j plus 1; the other r come from 1 to j. With r
equal to 3 and n equal to 7, the sum of C(3,3) to C(7,3) is 70, which is C(8, 4).

### Worked example

**Simple: a row and a coefficient.**

```ts
console.log([0, 1, 2, 3, 4, 5, 6].map(k => C(6, k)).join(' '));
console.log(C(7, 3), C(5, 2) * 4 * -27);
```

```text

```

**Realistic: checking identities numerically before proving them.**

```ts

console.log(C(9, 3), sum([0, 1, 2, 3].map(k => C(5, k) * C(4, 3 - k))));
console.log(sum([0, 1, 2, 3, 4, 5].map(k => C(5, k) ** 2)), C(10, 5));

```


A numerical check is not a proof, but it catches a wrong identity in seconds.

### Common mistake

**Dropping the sign or the constants in a binomial expansion.** The wrong way: the coefficient of x²y³ in
(2x minus 3y)⁵ as C(5, 3), 10. Why it fails: each term is C(n, j)(2x)ⁿ⁻ʲ(minus 3y)ʲ, so the constants come
along with their powers.

The fix is to substitute the whole of each summand, sign included, into the theorem.

**Misreading Pascal's identity bounds.** It needs k between 1 and n; at the edges C(n, 0) and C(n, n) are
1 and are the triangle's boundary.

### In real systems

Binomial coefficients appear in probability (the binomial distribution in chapter 7), in error-correcting
codes (how many error patterns of weight k), in combinatorial testing, and in computing C(n, k) mod a
prime for programming contests and cryptographic protocols. Pascal's triangle is the first dynamic
programming table most people meet: each entry from two smaller ones.

## 6.5 Generalized permutations and combinations

### In one sentence

When repetition is allowed, ordered selections number nʳ and unordered ones C(n plus r minus 1, r); when
some objects are identical, divide out their rearrangements; and distributing objects into boxes depends
on whether objects and boxes are distinguishable.

### The idea

#### Permutations with repetition

The number of r-permutations of n kinds of object with repetition allowed is nʳ, by the product rule. A
4-digit PIN has 10⁴ possibilities, 10,000.

#### Combinations with repetition: stars and bars

The number of r-combinations from n kinds with repetition allowed is C(n plus r minus 1, r). Picture the
choice as r stars and n minus 1 bars in a row: the bars split the stars into n groups, one per kind. Any
arrangement of r stars and n minus 1 bars is one selection, so count the ways to place the r stars among
n plus r minus 1 positions.

Choosing 6 doughnuts from 4 kinds: C(9, 6), which is 84. For example, 2 of kind one, none of kind two, 3
of kind three, 1 of kind four is the row of 2 stars, bar, bar, 3 stars, bar, 1 star.

#### Integer solutions of equations

The number of solutions of x1 plus x2 plus ... plus xₙ equal to r in non-negative integers is the same
count, C(n plus r minus 1, r). x1 plus x2 plus x3 plus x4 equal to 10 has C(13, 3), which is 286,
solutions. With lower bounds, such as xᵢ at least 1, first give each variable its minimum and count the
rest.

#### Permutations with indistinguishable objects

The number of different arrangements of n objects, with n1 identical of type 1, n2 of type 2, and so on,
is n!/(n1!·n2!·...·nₖ!). Arrangements of the letters of LETTER, with two Ts and two Es: 6!/(2!·2!), which
is 180.

Derivation: choose positions for the Ts, C(6, 2), then for the Es from the remaining 4, C(4, 2), then
place L and R, 2!. 15·6·2 is 180.

Assigning 12 distinct tasks to 3 people, 4 each: 12!/(4!·4!·4!), which is 34,650. Splitting 4 distinct
jobs into 2 unlabelled non-empty groups: the Stirling number S(4, 2), which is 7. Putting 6 identical
balls into 3 identical boxes: the partitions of 6 into at most 3 parts, which are 7.

### Common mistake

**Using stars and bars for distinguishable objects.** The wrong way: counting ways to assign 5 named

different assignment. The right count is 3⁵, which is 243.

**Forgetting the n minus 1.** n kinds need n minus 1 bars, so C(n plus r minus 1, r), not C(n plus r, r).

items with repeated types, which bounds what a scheduler must consider. Integer partitions appear in
bin-packing and in counting distinct load profiles.

## 6.6 Generating permutations and combinations

### In one sentence

Algorithms can list every permutation or combination of a set exactly once by moving from each one to
the next in lexicographic order, using a few simple swaps.

### The idea

#### Why generate

Sometimes counting is not enough: you need to try every arrangement, as in brute-force search, testing
every input order, or checking every subset for a property. Generating them in a fixed order makes the
search systematic and resumable.

#### Lexicographic order of permutations

Permutations of 1 to n are ordered like words in a dictionary: a1a2...aₙ precedes b1b2...bₙ if, at the
first position where they differ, a is smaller. For 1 2 3 the order is 123, 132, 213, 231, 312, 321.

#### The next permutation

To find the next permutation after a1...aₙ:

1. Find the largest j with aⱼ less than aⱼ₊₁. If none, this is the last permutation.
2. Find the largest k with aₖ greater than aⱼ. Swap aⱼ and aₖ.
3. Reverse the tail after position j, which puts it in increasing order.

The tail after j is decreasing before the swap, so it is the last arrangement of those elements; the
swap makes the smallest possible increase at position j; the reverse makes the tail the smallest
arrangement.

#### Generating subsets and combinations

Subsets of an n-element set correspond to bit strings of length n, so counting from 0 to 2ⁿ minus 1 in
binary lists them all. For r-combinations of 1 to n in lexicographic order: find the rightmost aᵢ that is
not at its maximum value, n minus r plus i; increase it by 1; set each later element to one more than the
one before.

### Worked example

**Simple: next permutation.**

```ts
function nextPerm(a: number[]) {
  a = [...a];
  let j = a.length - 2;
  while (j >= 0 && a[j] > a[j + 1]) j--;
  if (j < 0) return null;
  let k = a.length - 1;
  while (a[j] > a[k]) k--;
  [a[j], a[k]] = [a[k], a[j]];
  for (let r = a.length - 1, s = j + 1; r > s; r--, s++) [a[r], a[s]] = [a[s], a[r]];
  return a;
}
let p: number[] | null = [1, 2, 3]; const out: string[] = [];
while (p) { out.push(p.join('')); p = nextPerm(p); }
console.log(out.join(' '), '|', nextPerm([3, 1, 5, 4, 2])!.join(''));
```

```text
123 132 213 231 312 321 | 32145
```

**Realistic: next combination.**

```ts
function nextComb(a: number[], n: number) {
  a = [...a]; const r = a.length;
  let i = r - 1;
  while (i >= 0 && a[i] === n - r + i + 1) i--;
  if (i < 0) return null;
  a[i]++;
  for (let j = i + 1; j < r; j++) a[j] = a[i] + j - i;
  return a;
}
```

### Common mistake

**Generating permutations recursively and storing them all.** The wrong way: building an array of all
permutations of 12 items before testing any. Why it fails: 12! is 479,001,600, which will not fit in
memory.

The fix is a generator that yields one at a time, like `nextPerm` in a loop or a `function*`, and stopping
early when the answer is found.

**Off-by-one in the combination maximum.** The maximum for position i (from 1) is n minus r plus i;
getting it wrong skips or repeats combinations.

### In real systems

C++'s `std::next_permutation` uses exactly this algorithm. Exhaustive testers, puzzle solvers, small
optimisation searches and combinatorial test generators all enumerate permutations, combinations or
subsets in order, usually with early pruning; chapter 11's backtracking adds the pruning.

## From beginner to strategy

<Levels label="Chapter 6, Counting">
<Level name="Beginner" depth={3}>

The smallest working version: steps in sequence multiply, alternatives that cannot both happen add. With
those two rules you can count passwords, licence plates, menus and test matrices.

Worked example: a sandwich shop offers 3 breads, 5 fillings and 4 sauces, one of each. That is 3·5·4,
which is 60 sandwiches. If you may skip the sauce, sauces have 5 options, and there are 75.

The beginner mistake is adding when you should multiply, or the reverse. The fix is to say the task out
loud: "first ... then ..." means multiply; "either ... or ..." means add.

</Level>
<Level name="Intermediate" depth={3}>

At this level you decide whether order matters and whether repetition is allowed, which picks one of four
formulas, and you combine them with the product rule and complements.

Example: a team of 4 from 6 backend and 5 frontend engineers, with at least one of each. All teams minus
all-backend minus all-frontend: C(11, 4) minus C(6, 4) minus C(5, 4).

```ts
console.log(C(11, 4) - C(6, 4) - C(5, 4));
```

```text
310
```

The mistake is the "pick one of each, then any two" overcount, which gives 6·5·C(9, 2), 1,080. The fix is
complements, or disjoint cases by exact composition.

</Level>
<Level name="Advanced" depth={3}>

Underneath, counting is about bijections. Two sets have the same size exactly when there is a one-to-one
correspondence between them, and every formula in the chapter is a bijection to something easier: subsets
to bit strings, combinations with repetition to star-and-bar strings, solutions with lower bounds to
shifted solutions.

Combinatorial proofs make that explicit, and they generalise: the binomial theorem extends to
multinomials, Vandermonde to any number of groups, and pigeonhole to Ramsey theory, where the numbers
grow so fast that R(5, 5) is still unknown.

The mistake is proving identities only by algebra. The fix is to ask what each side counts; the proof
usually writes itself and explains the identity.

</Level>
<Level name="Edge cases" depth={3}>

- **r equal to 0.** C(n, 0) and P(n, 0) are 1: there is one way to choose nothing.
- **r greater than n.** C(n, r) and P(n, r) are 0 without repetition; with repetition they are fine.
- **0!.** It is 1, which makes the formulas work at the edges.
- **Empty set.** It has one subset, itself, and one permutation, the empty one.
- **Circular arrangements.** Divide by n for rotations, and by 2 more if reflections count as the same.
- **Lower bounds that exceed the total.** x1 plus x2 equal to 3 with each at least 2 has no solutions;
  the shifted total is negative.

</Level>
<Level name="Corner cases" depth={3}>

- **Floating point in C(n, r).** Large factorials overflow and lose precision; compute with a running
  product, or with `BigInt` above about C(60, 30).
- **Identical objects that look different.** Counting arrangements of a word with repeated letters as n!
  overcounts.
- **Pigeonhole with uneven boxes.** The bound ⌈N/k⌉ assumes all boxes are available; if some are
  restricted, recount.
- **Overlapping complements.** "At least one A or at least one B" needs inclusion–exclusion on the
  complements, not two subtractions.
- **Lexicographic order on non-numeric items.** Generators need a fixed comparison; JavaScript's default
  sort compares strings, so 10 comes before 9.

</Level>
<Level name="Production level" depth={3}>

In production, counting is how you size things before building them: ID spaces, key spaces, test
matrices, cache key cardinality, and the number of combinations a feature-flag system can produce. A
quick count prevents a test matrix of 4,096 jobs or an ID format that runs out in a year.

Generation is used for exhaustive testing of small domains and for fuzzing: enumerate all inputs up to a
size, then sample beyond. Keep generators lazy and resumable, and log the index so a failing case can be
reproduced.

The mistake is enumerating when counting would do. The fix is to count first; enumerate only if the
count is small enough to run.

</Level>
<Level name="Mindset" depth={3}>

The habit is to describe the object being counted precisely before reaching for a formula: what exactly
is one outcome, and when are two outcomes the same? Most counting errors are an unclear "same".

The second habit is to check small cases by brute force. Counting arguments are easy to get subtly
wrong, and a ten-line enumeration for n equal to 4 catches it.

</Level>
<Level name="System design" depth={3}>

In a larger system counting drives capacity and security. Collision probabilities for IDs depend on the
size of the space (pigeonhole and the birthday bound); brute-force resistance depends on key space;
sharding balance depends on how keys distribute into boxes.

Concrete system: a short-link service. With 7 base-62 characters there are 62⁷, about 3.5 × 10¹², codes.
At 100 million links, random codes collide often enough to need a uniqueness check, so the design uses a
counter encoded in base 62, or longer codes.

The mistake is sizing for today's volume. The fix is to count the space and compare it with ten years of
growth.

</Level>
<Level name="Strategy" depth={3}>

I learn this chapter by solving many small counting problems and checking each by brute force in code.
For every problem I write one sentence saying what one outcome is, then the formula, then a
ten-line enumeration for a small case.

Then I prove each identity in the chapter combinatorially from a blank page, and implement both
generators with tests that their output length equals the counting formula.

without overcounting, and prove Pascal's and Vandermonde's identities by double counting.

</Level>
</Levels>

## Questions people ask

**how do I know whether order matters?**

Swap two chosen items in your head. If the outcome changes (a ranking, a password), order matters. If it
does not (a team, a hand of cards), it does not.

**why is complement counting so common?**

"At least one" splits into many cases, but its complement, "none", is a single product. All minus none
is one subtraction.

**is there a formula for distributing distinct objects into identical boxes?**

Not a simple closed form. The count is a sum of Stirling numbers of the second kind, computed by a
recurrence.

**what does pigeonhole have to do with hashing?**

Any hash with fewer outputs than inputs must map two inputs to one output. Good hashes make collisions
rare and hard to find, not impossible.

## Key takeaways

- Sequences of steps multiply; disjoint alternatives add; overlaps are subtracted; uniform overcounts are
  divided.
- n objects into fewer than n boxes forces a shared box; N into k forces one with at least ⌈N/k⌉.
- R(3, 3) is 6: any 6 people include 3 mutual friends or 3 mutual strangers.
- P(n, r) counts ordered selections and C(n, r) unordered ones; P(n, r) is C(n, r)·r!.
- The binomial theorem's coefficients are C(n, k); Pascal's identity builds the triangle.
- Combinatorial proofs count one set two ways or give a bijection.
- With repetition: nʳ ordered, C(n plus r minus 1, r) unordered; identical objects divide by their
  rearrangements.
- Next permutation and next combination list every arrangement once, in lexicographic order.

## Glossary

- **Product rule**: a sequence of tasks multiplies the counts.
- **Sum rule**: disjoint alternatives add.
- **Subtraction rule**: add, then subtract the overlap; two-set inclusion–exclusion.
- **Division rule**: divide when each outcome is counted d times.
- **Tree diagram**: branches for choices, leaves for outcomes.
- **Pigeonhole principle**: more objects than boxes forces a shared box.
- **Generalised pigeonhole**: N objects in k boxes force one with at least ⌈N/k⌉.
- **Ramsey number R(m, n)**: least size guaranteeing m mutual friends or n mutual strangers.
- **Permutation, r-permutation**: an ordered arrangement of all, or of r, elements.
- **Combination, r-combination**: an unordered selection, an r-subset.
- **P(n, r), C(n, r)**: n!/(n minus r)!; n!/(r!(n minus r)!).
- **Combinatorial proof**: double counting or a bijection.
- **Binomial theorem**: (x plus y)ⁿ is the sum of C(n, j)xⁿ⁻ʲyʲ.
- **Pascal's identity, Pascal's triangle**: C(n plus 1, k) is C(n, k minus 1) plus C(n, k); the table it
  builds.
- **Vandermonde's identity**: C(m plus n, r) is the sum of C(m, r minus k)C(n, k).
- **Stars and bars**: C(n plus r minus 1, r) for selections with repetition.
- **Multinomial coefficient**: n!/(n1!·...·nₖ!) for arrangements with identical objects.
- **Stirling number of the second kind**: ways to split n distinct objects into k non-empty unlabelled
  groups.
- **Integer partition**: a way to write n as a sum of positive integers, ignoring order.
- **Lexicographic order**: dictionary order on sequences.
