## Why this book

This is the primary book for phase 7 of the <a href={withBase('/plans/traditional-software-developer/')}>traditional core</a>,
networks. I spend my working day at the top of the stack, in HTTP clients, fetch calls and API servers, and this
book starts exactly there and walks down: application, transport, network, link, then wireless and security.
That order means every chapter explains what is underneath something I already use.

The chapters below follow the ninth edition's contents on the publisher's page, which also lists every
section; I name the sections each chapter covers rather than giving each its own heading.

## How I would learn it

I would read one chapter every few days, with Wireshark open and a capture running. For each idea I find the
packet that shows it: the DNS query, the TCP handshake, the TLS hello, the ARP request. I do every socket
exercise twice, once in C with the raw calls and once with Node's `net` and `dgram`. Stanford's CS144 and
Beej's guide are my build track; TCP/IP Illustrated is the reference when I need the exact field.

## Down the stack

### 1. Computer Networks and the Internet
**Covers:** What the Internet is, the network edge and access networks, the core with packet and circuit switching, delay, loss and throughput, protocol layers and encapsulation, attacks, and a short history.

<Levels label="Chapter 1, Computer Networks and the Internet">

<Level name="Beginner">

The Internet is millions of connected devices (hosts) exchanging packets through routers and links, run by protocols that everyone agrees on. A packet is a chunk of data with a header saying where it goes.

</Level>

<Level name="Intermediate">

Hosts reach the Internet through access networks (home broadband, cellular, enterprise Ethernet and WiFi). The core is a mesh of routers doing store-and-forward packet switching. Delay at each hop is processing plus queuing plus transmission (size divided by link rate) plus propagation (distance divided by signal speed).

</Level>

<Level name="Advanced">

Queuing delay grows sharply as traffic intensity approaches 1, and packets are dropped when a queue is full. Throughput end to end is bounded by the slowest link. Layers (application, transport, network, link, physical) each add a header around the layer above's data: encapsulation.

</Level>

<Level name="Edge cases">

A 1 KB packet on a fast link across an ocean is dominated by propagation, while a large file on a slow access link is dominated by transmission. Mixing up the two leads to the wrong fix.

</Level>

<Level name="Corner cases">

Traffic intensity near 1 on a link that is also far away gives high and very variable latency: queuing and propagation stack, which is what makes video calls stutter across continents on busy links.

</Level>

<Level name="Production level">

Latency, not bandwidth, limits most web pages; round trips are the expensive unit. Attacks (malware, denial of service, sniffing, spoofing) shape every later design choice.

</Level>

<Level name="Mindset">

Separate the four kinds of delay before guessing a cause. Measure, then name the component.

</Level>

<Level name="System design">

Choosing regions, CDNs and connection reuse are decisions about propagation and round trips.

</Level>

<Level name="Strategy">

I would run `traceroute` to three distant hosts and explain each hop's time, and compute delays for a few made-up links by hand. Done when I can tell which delay dominates a described situation.

</Level>
</Levels>

### 2. Application Layer
**Covers:** Principles of network applications, the Web and HTTP (including HTTP/2, HTTP/3 and QUIC), email, DNS, video streaming and content distribution networks, and socket programming with UDP, TCP and QUIC.

<Levels label="Chapter 2, Application Layer">

<Level name="Beginner">

Applications talk over the network with protocols they define, usually client-server. HTTP is a request-response protocol: the client sends a method, a path and headers; the server answers with a status, headers and a body. DNS turns names into addresses.

</Level>

<Level name="Intermediate">

HTTP/1.1 reuses connections; cookies add state to a stateless protocol; caches and conditional requests avoid re-downloading. DNS is a distributed hierarchy (root, top-level domain, authoritative servers) with caching resolvers in front. CDNs place content near users and use DNS or anycast to steer them.

</Level>

<Level name="Advanced">

HTTP/2 multiplexes streams over one TCP connection with binary framing and header compression, but a lost TCP segment still blocks every stream. HTTP/3 runs over QUIC, on UDP, with per-stream reliability and TLS 1.3 built in, so one lost packet only stalls its own stream. Socket programming exposes the transport choice directly.

</Level>

<Level name="Edge cases">

A DNS record with a long TTL keeps clients on an old address for hours after a migration. A response with no caching headers may still be cached heuristically.

</Level>

<Level name="Corner cases">

HTTP/2 over a lossy mobile link can be slower than several HTTP/1.1 connections, because all streams share one TCP connection's head-of-line blocking; HTTP/3 was designed around exactly that corner.

</Level>

<Level name="Production level">

Most outages that look like "the network" are DNS: an expired domain, a bad record, a low TTL forgotten before a change. Cache headers, compression and connection reuse are the cheapest performance wins.

</Level>

<Level name="Mindset">

Every application protocol answers the same questions: who speaks first, how messages are framed, how state is kept, how errors are reported.

</Level>

<Level name="System design">

API design, caching layers and CDN strategy are all chapter 2 decisions.

</Level>

<Level name="Strategy">

I would write a minimal HTTP/1.1 server over raw TCP in Node, trace a full resolution with `dig +trace`, and compare `curl --http1.1`, `--http2` and `--http3` on one site. Done when my server serves a static file correctly to curl and a browser.

</Level>
</Levels>

### 3. Transport Layer
**Covers:** Transport services, multiplexing and demultiplexing, UDP, principles of reliable data transfer (including Go-Back-N and Selective Repeat), TCP (connection, segment structure, RTT estimation and timeout, reliable transfer, flow control, connection management), principles of congestion control, TCP congestion control (classic and recent, ECN, fairness), and the evolution of transport protocols.

<Levels label="Chapter 3, Transport Layer">

<Level name="Beginner">

The transport layer delivers data between processes, using port numbers. UDP adds only ports and a checksum. TCP adds connections, ordered reliable delivery, flow control and congestion control.

</Level>

<Level name="Intermediate">

Reliable transfer is built from checksums, sequence numbers, acknowledgements, timers and retransmission. Pipelining (many packets in flight) needs Go-Back-N or Selective Repeat. TCP sets up a connection with a three-way handshake, tracks bytes with sequence numbers, and estimates round-trip time to set its timeout.

</Level>

<Level name="Advanced">

Flow control keeps a sender from overrunning the receiver's buffer (the advertised window). Congestion control keeps senders from overrunning the network: classic TCP grows its window additively and halves it on loss (AIMD), with slow start at the beginning; recent algorithms such as CUBIC and BBR model the network differently. ECN lets routers signal congestion without dropping packets.

</Level>

<Level name="Edge cases">

A zero receive window stops the sender until the receiver opens it again, which is why TCP probes the window. A very short timeout causes spurious retransmissions; a very long one makes loss recovery slow.

</Level>

<Level name="Corner cases">

Many short connections each spend their life in slow start, never reaching full speed, while also leaving TIME_WAIT behind; connection reuse fixes both at once.

</Level>

<Level name="Production level">

Throughput of one TCP connection is limited by window divided by round-trip time, so high-latency links need large windows. Retransmission and congestion show up as tail latency, not average latency.

</Level>

<Level name="Mindset">

Reliability is a protocol you build out of unreliable parts, and every reliable protocol makes the same four choices: detect, acknowledge, time out, retransmit.

</Level>

<Level name="System design">

Message queues, RPC retries and database replication all reinvent pieces of reliable data transfer.

</Level>

<Level name="Strategy">

I would build a stop-and-wait, then a Go-Back-N protocol over UDP in Node and test it with loss added by `tc netem`. Done when a file arrives intact at 10 per cent loss and I can explain the throughput I measure.

</Level>
</Levels>

### 4. The Network Layer: Data Plane
**Covers:** An overview of the network layer, what is inside a router, the Internet Protocol (IPv4 datagrams, addressing, NAT, IPv6), generalized forwarding and software-defined networking, and the architectural principles of the Internet.

<Levels label="Chapter 4, The Network Layer: Data Plane">

<Level name="Beginner">

The network layer moves packets from host to host across routers. Each router looks at the destination IP address and forwards the packet out the right link: that is the data plane.

</Level>

<Level name="Intermediate">

IPv4 addresses are 32 bits written as four numbers; networks are blocks written in CIDR notation like `10.0.0.0/16`. Routers forward by longest-prefix match. NAT lets many private addresses share one public address by rewriting ports. IPv6 uses 128-bit addresses and a simpler header.

</Level>

<Level name="Advanced">

Inside a router are input ports, a switching fabric, output ports and queues; packets are dropped when output queues overflow, and scheduling decides which packet goes next. Generalized forwarding matches on many header fields and takes actions (forward, drop, rewrite), the idea behind SDN and OpenFlow.

</Level>

<Level name="Edge cases">

A packet larger than a link's MTU is fragmented in IPv4 or dropped with an ICMP message in IPv6; blocked ICMP breaks path MTU discovery and causes mysterious hangs.

</Level>

<Level name="Corner cases">

NAT breaks the end-to-end model: a host behind NAT cannot accept incoming connections without port forwarding or relays, and two hosts behind NATs need hole punching or a relay to talk at all.

</Level>

<Level name="Production level">

Subnetting, private address ranges, security groups and NAT gateways are everyday cloud configuration; most cloud networking bugs are a wrong CIDR or a missing route.

</Level>

<Level name="Mindset">

Separate forwarding (per packet, fast, local) from routing (global, slow, computed). Many systems benefit from the same split.

</Level>

<Level name="System design">

Load balancers, firewalls and NATs are middleboxes; the architectural principles explain the trade-off they make against the end-to-end argument.

</Level>

<Level name="Strategy">

I would write a subnet calculator in TypeScript, design a VPC with public and private subnets on paper, and watch NAT rewrite ports with `conntrack`. Done when I can answer whether two addresses are on the same subnet instantly.

</Level>
</Levels>

### 5. The Network Layer: Control Plane
**Covers:** Routing algorithms (link-state and distance-vector), intra-domain routing with OSPF, inter-domain routing with BGP, the SDN control plane, ICMP, and network management with SNMP, NETCONF and YANG.

<Levels label="Chapter 5, The Network Layer: Control Plane">

<Level name="Beginner">

The control plane decides the routes that the data plane follows. Routers run routing algorithms to fill in their forwarding tables.

</Level>

<Level name="Intermediate">

Link-state routing floods the whole topology to every router, which runs Dijkstra's shortest path. Distance-vector routing has each router share its distances with neighbours and update with Bellman-Ford. OSPF is link-state inside one organisation; BGP connects organisations (autonomous systems).

</Level>

<Level name="Advanced">

BGP is policy routing: each network chooses routes by business relationships and advertises paths, not costs. SDN centralises the control plane in a controller that programs switches. ICMP carries errors and diagnostics (ping, traceroute rely on it).

</Level>

<Level name="Edge cases">

Distance-vector suffers count-to-infinity when a link fails, slowly increasing distances in a loop; poisoned reverse helps only in simple cases.

</Level>

<Level name="Corner cases">

A wrong BGP announcement from one network can attract traffic for addresses it does not own (a route leak or hijack), and the whole Internet follows it until fixed.

</Level>

<Level name="Production level">

Several famous outages were BGP: a misconfiguration withdrew a company's routes and its services, including its DNS, vanished from the Internet.

</Level>

<Level name="Mindset">

Local decisions plus shared information produce global behaviour, for better or worse.

</Level>

<Level name="System design">

Anycast, which puts one address in many places and lets BGP pick the nearest, is how CDNs and public DNS resolvers work.

</Level>

<Level name="Strategy">

I would implement Dijkstra and a distance-vector simulation on a small graph, then fail a link in both. Done when I can show count-to-infinity happening and explain why link-state avoids it.

</Level>
</Levels>

### 6. The Link Layer and LANs
**Covers:** Link layer services, error detection and correction, multiple access links and protocols (including cable access with DOCSIS), switched LANs (addressing and ARP, Ethernet, switches, VLANs), link virtualization with MPLS and VXLANs, data center networking, and a day in the life of a web request.

<Levels label="Chapter 6, The Link Layer and LANs">

<Level name="Beginner">

The link layer moves frames across one link between neighbours. Ethernet frames carry MAC addresses; ARP finds the MAC address for an IP address on the local network.

</Level>

<Level name="Intermediate">

Error detection uses parity, checksums and CRCs. Shared media need multiple access protocols (random access like CSMA/CD, taking turns). Switches learn which MAC address is on which port and forward frames only where needed; VLANs split one physical switch into several logical networks.

</Level>

<Level name="Advanced">

Data center networks use layered or Clos topologies with many equal paths, and overlays such as VXLAN carry virtual networks over the physical one. MPLS forwards by labels instead of IP lookups. The chapter ends by tracing a web request through DHCP, ARP, DNS, TCP and HTTP across every layer.

</Level>

<Level name="Edge cases">

An ARP entry pointing at the wrong MAC (after a failover, or through spoofing) silently sends traffic to the wrong machine until it expires.

</Level>

<Level name="Corner cases">

A loop of switches without spanning tree forwards broadcast frames forever and takes the network down in seconds.

</Level>

<Level name="Production level">

Cloud networks are overlays; MTU mismatches between overlay and underlay are a classic cause of connections that hang on large responses only.

</Level>

<Level name="Mindset">

Every layer solves the same problems (addressing, error detection, sharing the medium) at its own scope.

</Level>

<Level name="System design">

The day in the life of a web request is the gate of phase 7 written out; it ties every layer together.

</Level>

<Level name="Strategy">

I would capture a cold page load from a fresh network join (DHCP, ARP, DNS, TCP, TLS, HTTP) and label every packet. Done when I can tell the day-in-the-life story from my own capture.

</Level>
</Levels>

## Beyond the wired core

### 7. Wireless and Mobile Networks
**Covers:** The physical layer of wireless networks (channel characteristics, coding and modulation), the wireless access network (sharing the channel, WiFi, the 5G radio access network, discovery, scheduling, energy), the wireless core network (the 5G core), mobility in WiFi and 5G, and Bluetooth, satellite and IoT networks.

<Levels label="Chapter 7, Wireless and Mobile Networks">

<Level name="Beginner">

Wireless links lose more packets, change quality constantly, and are shared by everyone nearby. WiFi connects devices to an access point; cellular networks connect phones to base stations and a mobile core.

</Level>

<Level name="Intermediate">

802.11 uses CSMA/CA because collisions cannot be detected while transmitting; it acknowledges every frame and can reserve the channel with RTS and CTS. Cellular networks separate the radio access network from the core, which handles authentication, mobility and connection to the Internet.

</Level>

<Level name="Advanced">

Mobility keeps connections alive as a device moves, through indirect routing via a home network or direct routing, and through handovers between base stations. 5G adds flexible radio, a service-based core and network slicing.

</Level>

<Level name="Edge cases">

The hidden-terminal problem: two stations that cannot hear each other both transmit to the same access point and collide.

</Level>

<Level name="Corner cases">

TCP treats wireless loss as congestion and slows down, even though the network is not congested; link-layer retransmission hides most loss to avoid this.

</Level>

<Level name="Production level">

Mobile clients see high and variable latency and frequent address changes; QUIC's connection IDs survive address changes where TCP connections do not.

</Level>

<Level name="Mindset">

The medium shapes the protocol. Assumptions from wired networks fail on radio.

</Level>

<Level name="System design">

Mobile-first APIs need retries, idempotency and small payloads because of this chapter.

</Level>

<Level name="Strategy">

I would read the chapter more lightly than the others and compare a page load on WiFi and on a phone hotspot with Wireshark. Done when I can explain the latency difference.

</Level>
</Levels>

### 8. Security in Computer Networks
**Covers:** What network security is, principles of cryptography, message integrity and digital signatures, end-point authentication, securing email, securing TCP connections with TLS (including TLS 1.3), network-layer security with IPsec and VPNs, securing wireless and 5G, and operational security with firewalls and intrusion detection.

<Levels label="Chapter 8, Security in Computer Networks">

<Level name="Beginner">

Network security gives confidentiality, integrity, authentication and availability over a network anyone can watch. Encryption hides content; signatures and message authentication codes prove origin and integrity.

</Level>

<Level name="Intermediate">

Symmetric encryption is fast and needs a shared key; public-key cryptography solves key exchange and signatures. Certificates signed by certificate authorities bind public keys to names. TLS combines all of these to secure a TCP connection.

</Level>

<Level name="Advanced">

TLS 1.3 finishes its handshake in one round trip: key exchange with ephemeral Diffie-Hellman for forward secrecy, certificate verification, then encrypted application data. IPsec secures traffic at the network layer and underlies many VPNs. Firewalls filter packets; intrusion detection systems look inside them.

</Level>

<Level name="Edge cases">

A certificate valid for `example.com` does not cover `api.example.com` unless it lists it or uses a wildcard; an expired intermediate breaks clients that do not have it cached.

</Level>

<Level name="Corner cases">

Resuming a TLS session with zero round trips (0-RTT) is fast but lets an attacker replay the first request, so only idempotent requests are safe there.

</Level>

<Level name="Production level">

Expired certificates are among the most common causes of outages; automate renewal and monitor expiry. Terminate TLS deliberately and know where traffic is plain text.

</Level>

<Level name="Mindset">

Ask what each mechanism proves and to whom. Encryption without authentication proves nothing about who you are talking to.

</Level>

<Level name="System design">

Where TLS terminates (CDN, load balancer, service) is a security architecture decision, and mutual TLS between services is the zero-trust version.

</Level>

<Level name="Strategy">

I would read a TLS 1.3 handshake with `openssl s_client -connect` and in Wireshark, and serve my HTTP server over TLS with a local certificate. Done when I can narrate every message of the handshake.

</Level>
</Levels>

## Misreadings to avoid

- "Bandwidth is speed." For most requests, round trips and latency matter more than bandwidth.
- "TCP guarantees delivery." TCP guarantees order and retransmission while the connection lives; it cannot tell you whether the application on the other end processed your data.
- "UDP is unreliable, so never use it." UDP is a base for protocols that want their own reliability, like QUIC, DNS and real-time media.
- "HTTPS hides everything." It hides content, but the server name (unless encrypted), IP addresses, sizes and timing are visible.
- "The layers are strict." Real systems cross layers all the time: NAT rewrites transport ports, load balancers read HTTP.
