## Why this book

This is the depth book for <a href={withBase('/plans/traditional-software-developer/#strategy-4')}>phase 4, algorithms</a>
of the traditional core. <a href={withBase('/books/the-algorithm-design-manual/')}>The Algorithm Design Manual</a>
is the primary book: it teaches me how to recognise and model a problem.
CLRS is where I go when I need the proof: why Dijkstra is correct, why the
master method gives the bound it gives, why a red–black tree stays balanced.

It is a reference, not a cover-to-cover read. At more than thirty chapters it
covers far more than the phase needs. I read the chapters a phase 4 build
touches, and treat the rest as a map of what exists. The book writes its
algorithms in pseudocode; my examples are TypeScript, the phase's language.

## How I would learn it

I would never open CLRS first. For each phase 4 topic I solve problems with
Skiena's framing, write the code, and only then open the CLRS chapter to read
the proof. Reading a proof of an algorithm I have already implemented is a
different experience from reading it cold: every invariant maps to a line I
wrote, and every case in the proof maps to a test I should have.

For each chapter I read, I write the loop invariant or the key lemma in my
own words at the top of my implementation, as a comment, and then try to
break it with a property test. I do a handful of the exercises at the end of
each section, the ones whose answers I cannot guess, and skip the
problems at the chapter ends on the first pass.

Every chapter now has its own page below, written to be learned from on
its own: each section of the book taught from first principles, with my own
TypeScript, traces, proofs walked line by line, the nine levels from
beginner to strategy, exercises and a study plan. The book page is the map;
the chapter pages are the territory.

Phase 4 is seven weeks (weeks 17 to 23). CLRS fills in behind Skiena, one
proof-level chapter per topic, and stays on the desk for the rest of the
roadmap.

## What I learn from it

One line per chapter, the skill I can show when the chapter is done.

- [ ] **1. The Role of Algorithms in Computing**: say what makes a procedure an algorithm, what correct means, and why algorithms are a technology that beats faster hardware.
- [ ] **2. Getting Started**: prove a loop correct with an invariant, count steps in the RAM model, and solve merge sort's recurrence.
- [ ] **3. Characterizing Running Times**: prove O, Ω and Θ claims from the definitions with explicit constants, and order the standard functions.
- [ ] **4. Divide-and-Conquer**: solve recurrences by substitution, recursion trees and the master method, and explain Strassen's trick.
- [ ] **5. Probabilistic Analysis and Randomized Algorithms**: use indicator random variables for expected cost, and randomise to defeat bad inputs.
- [ ] **6. Heapsort**: build a heap in linear time, sort with it, and run a priority queue.
- [ ] **7. Quicksort**: partition correctly, and derive randomized quicksort's expected Θ(n lg n).
- [ ] **8. Sorting in Linear Time**: prove the comparison-sort lower bound, and use counting, radix and bucket sort where they apply.
- [ ] **9. Medians and Order Statistics**: select the k-th smallest in expected and worst-case linear time.
- [ ] **10. Elementary Data Structures**: build stacks, queues, linked lists and rooted-tree representations on arrays and pointers.
- [ ] **11. Hash Tables**: implement chaining and open addressing, pick hash functions, and reason about load factor.
- [ ] **12. Binary Search Trees**: search, insert and delete in a BST, including the two-child delete.
- [ ] **13. Red-Black Trees**: state the five properties, rotate, and fix up after insert and delete.
- [ ] **14. Dynamic Programming**: define a state, prove optimal substructure, and fill the table bottom-up or with memoisation.
- [ ] **15. Greedy Algorithms**: prove a greedy choice with an exchange argument, and build Huffman codes.
- [ ] **16. Amortized Analysis**: use aggregate, accounting and potential arguments on a dynamic table.
- [ ] **17. Augmenting Data Structures**: add subtree sizes or interval data to a tree and keep it correct under rotations.
- [ ] **18. B-Trees**: explain B-tree height, split nodes on the way down, and delete keys.
- [ ] **19. Data Structures for Disjoint Sets**: write union-find with union by rank and path compression.
- [ ] **20. Elementary Graph Algorithms**: run BFS, DFS, topological sort and strongly connected components.
- [ ] **21. Minimum Spanning Trees**: prove the cut property and implement Kruskal and Prim.
- [ ] **22. Single-Source Shortest Paths**: run Bellman-Ford, DAG shortest paths and Dijkstra, and know why negative edges break Dijkstra.
- [ ] **23. All-Pairs Shortest Paths**: use Floyd-Warshall and Johnson's reweighting.
- [ ] **24. Maximum Flow**: compute max flow with augmenting paths and read off a minimum cut.
- [ ] **25. Matchings in Bipartite Graphs**: find maximum matchings, stable matchings and optimal assignments.
- [ ] **26. Parallel Algorithms**: measure work and span, and parallelise loops, matrix multiply and merge sort.
- [ ] **27. Online Algorithms**: reason about competitive ratios for rent-or-buy, list updates and caching.
- [ ] **28. Matrix Operations**: solve linear systems with LUP decomposition and fit least squares.
- [ ] **29. Linear Programming**: formulate problems as linear programs and read their duals.
- [ ] **30. Polynomials and the FFT**: multiply polynomials in Θ(n lg n) with the FFT.
- [ ] **31. Number-Theoretic Algorithms**: run Euclid, modular arithmetic, CRT, fast powers, RSA and primality tests.
- [ ] **32. String Matching**: implement naive, Rabin-Karp, automaton and KMP matching, and build a suffix array.
- [ ] **33. Machine-Learning Algorithms**: run k-means, multiplicative weights and gradient descent, and say what each guarantees.
- [ ] **34. NP-Completeness**: define P and NP, and reduce one NP-complete problem to another in the right direction.
- [ ] **35. Approximation Algorithms**: state and prove the guarantee of vertex cover, TSP, set cover and subset-sum approximations.
- [ ] **Appendices A to D**: bound sums, use sets, relations, graphs and trees, count and reason about probability, and handle matrices.

## Misreadings to avoid

- "CLRS is the book to learn algorithms from first." It is the reference for
  proofs. A design-first book and practice problems come first.
- "Pseudocode is ready to paste." The book indexes arrays from 1 and leaves
  out overflow, recursion depth and error handling.
- "If it is in CLRS, it is what production uses." Libraries use tuned
  hybrids: TimSort, introsort, B+ trees, Swiss tables.
- "Asymptotic bounds decide everything." Constants and memory layout decide
  most real comparisons at production sizes.
- "NP-hard means I cannot solve it." It means no known algorithm is fast on
  every input; real inputs are often tractable.
- "Reading the proof is enough." Writing the code and a property test is
  what shows I understood it.

## Done with this book when

- For every phase 4 build I can open the matching chapter and explain the
  correctness argument behind my code.
- My sorting benchmark, route planner, LCS diff and KMP search each have the
  invariant or lemma written at the top of the file.
- I can solve a recurrence, write a reduction and prove a greedy choice
  without looking anything up.
- I can pass the phase 4 gate: pick an algorithm for an unseen problem, state
  its cost, and say why it is correct.
