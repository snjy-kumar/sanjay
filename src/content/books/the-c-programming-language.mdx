## Why this book

The <a href={withBase('/plans/traditional-software-developer/')}>traditional core</a> names this as the
alternative C book for phase 1, programming from first principles. It is short, dense and old, and it
was written by the people who made the language. I read
<a href={withBase('/books/c-programming-a-modern-approach/')}>King's book</a> for the exercises and the
gentle path, and I keep this one next to it as the compact statement of how C thinks.

It is also a model of technical writing. Every chapter is a few pages of explanation and then a real
program that uses it: a word counter, a sort, a hash table lookup, a memory allocator. That is the
shape of the phase 1 gate too: a small tool, every line explained. The
<a href={withBase('/plans/traditional-software-developer/#strategy-1')}>phase 1 strategy</a> leans on it
as the second read of each idea.

The book describes ANSI C (C89). The C I compile today is C99 or C11 or later, so I note where a
later standard changed something, and I never take its code as a security example: it predates most
of what we now know about buffer overflows.

## How I would learn it

I read it after the matching King chapter, not before. King explains; Kernighan and Ritchie compress.
Reading the compressed version after the explanation is a test: if a paragraph here surprises me, I
did not really understand the King chapter.

Each chapter, I type every program, compile it with `-std=c99 -Wall -Wextra -pedantic
-fsanitize=address,undefined`, and fix whatever the modern compiler complains about. Then I do two or
three exercises, the ones that change the program rather than the ones that repeat it. Where a
program reads input, I feed it an empty file, a file with no final newline, and a very long line,
because those are the phase 1 gate's cases.

## What I learn from it

- **Chapter 1, A Tutorial Introduction.** Compile and run a program; variables, integer and float arithmetic, `while`, `for`, `#define`; `getchar`, `putchar` and `EOF`; the copy, count and word-count filters; arrays; functions and prototypes; call by value; strings as zero-terminated arrays; external variables.
- **Chapter 2, Types, Operators, and Expressions.** Names; the basic types and their sizes; constants of every kind; declarations and `const`; arithmetic, relational and logical operators; the implicit conversions; `++` and `--`; the bitwise operators; compound assignment; the conditional operator; precedence and the order of evaluation.
- **Chapter 3, Control Flow.** Statements and blocks; `if`-`else` and the dangling else; `else if` chains and binary search; `switch` and fall-through; `while` and `for`; `do`-`while`; `break` and `continue`; `goto` and labels.
- **Chapter 4, Functions and Program Structure.** Function basics and the grep-like example; functions returning non-integers; external variables and the calculator; scope rules; header files; static variables; register variables; block structure; initialisation; recursion and quicksort; the preprocessor: inclusion, macros, conditional compilation.
- **Chapter 5, Pointers and Arrays.** Pointers and addresses; pointers as function arguments; how arrays and pointers relate; address arithmetic and a simple allocator; character pointers and the string functions; arrays of pointers and sorting lines; multi-dimensional arrays; initialising pointer arrays; pointers versus 2D arrays; command-line arguments; pointers to functions; reading complicated declarations.
- **Chapter 6, Structures.** Structure basics; structures and functions; arrays of structures and keyword counting; pointers to structures; self-referential structures and binary trees; a hash-table lookup; `typedef`; unions; bit-fields.
- **Chapter 7, Input and Output.** Standard input and output; `printf` in full; variable-length argument lists; `scanf`; opening files; `stderr` and `exit`; line input and output; the miscellaneous library: strings, character classes, `ungetc`, `system`, storage management, maths, random numbers.
- **Chapter 8, The UNIX System Interface.** File descriptors; `read` and `write`; `open`, `creat`, `close`, `unlink`; `lseek`; an implementation of `fopen` and `getc`; listing directories; a storage allocator.
- **Appendix A, Reference Manual.** The exact rules: lexical conventions, identifiers, objects and lvalues, conversions, expressions, declarations, statements, external declarations, scope and linkage, preprocessing, and the grammar; plus Appendix C's summary of changes since the first edition.
- **Appendix B, Standard Library.** Every header of the C89 library: `stdio.h`, `ctype.h`, `string.h`, `math.h`, `stdlib.h`, `assert.h`, `stdarg.h`, `setjmp.h`, `signal.h`, `time.h`, `limits.h` and `float.h`.

## Misreadings to avoid

- "Short means simple." The book is short because it is dense; every paragraph carries a rule.
- "The code is a security model." It is a teaching model from 1988; its string handling is unsafe by
  today's standards.
- "ANSI C is current C." C99, C11 and later added `//` comments, `stdint.h`, `bool`, designated
  initialisers and much more.
- "Undefined behaviour means a crash." It means the language makes no promise at all, including that
  the program looks fine today.
- "K&R or King." They do different jobs: one explains, one compresses. Use both.
