Arrays vs tuples

1 October 2026 · about 5 min · Published

What it is

An array type number[] means “zero or more numbers, order does not change the type of each slot.” That is correct for a list of scores. It is the wrong model for a coordinate, where index 0 is latitude, index 1 is longitude, and a third number is not a plan.

A tuple fixes the length and the type at each position: [number, number] or [string, number]. Extra elements, missing elements, and a string in the latitude slot fail to assign. Arrays say the length may grow. Tuples say the shape is part of the contract. If the positions have names that readers must remember, an object is often clearer than either — the point of the tuple is a short, ordered pair, not a secret struct.

A map pin in a personal project is stored as [lat, lng] because that is the order a small helper already expects, and a chart series is a list of [label, value] pairs such as ["views", 120] before those records grow enough fields to deserve an object. Typing both as number[] or (string | number)[] lets a third coordinate through and lets the label and the value swap places.

The code

The extra element is legal. Nothing names which index is which.

array.ts 
1const point: number[] = [10, 20, 30];


2point.push(40);


3


4const lat = point[0];


5const lng = point[1];


6const mystery = point[2];

A tuple stops the extra element and keeps each position’s type.

tuple.ts 
1type Point = [number, number];


2type Entry = [string, number];


3


4const point: Point = [10, 20];


5const entry: Entry = ["views", 120];


6


7const [lat, lng] = point;


8const [label, views] = entry;


9


10// const tooLong: Point = [10, 20, 30];


11// const swapped: Entry = [120, "views"];

A rest element is still a tuple: a label, then a fixed pair, then a list. Use that only when the prefix really is fixed. For a named coordinate, the object is the better public type and the tuple can stay at the boundary.

located.ts 
1type Located = { lat: number; lng: number };


2


3function toPoint(pin: Located): Point {


4  return [pin.lat, pin.lng];


5}


6


7function fromPoint(point: Point): Located {


8  const [lat, lng] = point;


9  return { lat, lng };


10}

Old

Wrong approach: an array wherever there is a list

Best case. The array really is a list: search results, tags, log lines. Length changes, and every element means the same thing. A tuple would fight the domain.

Worst case. You meant a coordinate. push adds a third number, a bug swaps latitude and longitude, both still type-check, and the pin is simply wrong on the map. A pair typed as (string | number)[] makes you narrow on every read.

Before: the pin is “some numbers,” and the view series is “some strings or numbers.”

before.ts 
1function distance(a: number[], b: number[]): number {


2  const dx = a[0] - b[0];


3  const dy = a[1] - b[1];


4  return Math.hypot(dx, dy);


5}


6


7function formatEntry(pair: (string | number)[]): string {


8  return String(pair[0]) + ": " + String(pair[1]);


9}

New

Right approach: a tuple when position is the API

Best case. [number, number] rejects a third value and a non-number. Destructuring names the positions at the use site. Helpers that talk to a library expecting [lat, lng] stay honest without a class.

Worst case. An eight-element tuple with no labels. Callers pass arguments in the wrong order and the types still line up because too many slots share a type. At that size, switch to an object. Tuples also widen in unannotated literals sometimes (as const or an explicit annotation fixes inference). A tuple does not validate a runtime array from JSON; you still parse length and types before asserting the tuple.

After: both helpers take a fixed pair. The distance function cannot be called with a 3D point by accident. The formatter knows which side is text.

after.ts 
1function distance(a: Point, b: Point): number {


2  const [ax, ay] = a;


3  const [bx, by] = b;


4  return Math.hypot(ax - bx, ay - by);


5}


6


7function formatEntry(pair: Entry): string {


8  const [label, value] = pair;


9  return label + ": " + value;


10}

When to use which

Use T[] when the length is allowed to change and every index has the same meaning. Use a tuple for pairs and other short fixed records: coordinates, [string, number] entries, a function that returns [value, error]. Prefer an object once the positions need names to be readable. Annotate the tuple (or use as const for a literal you do not intend to widen). At a JSON boundary, check Array.isArray, length, and element types, then return the tuple type — do not cast a raw array.
